# max-hack — коллективные заявки по общему имуществу МКД в MAX

Чат-бот + мини-приложение в мессенджере MAX (хакатон MAX, трек «Умный город»): жители превращают хаос сообщений в домовом чате в одну доказательную заявку с ответственным, нормативным сроком и живым статусом.

**Статус (25.09.2026):** бэкенд, мини-приложение (дом, заявка, форма в 3 шага, дубль, очередь УК со сменой статуса), живая карточка через outbox и диалог бота готовы; нужен деплой и проверка в MAX. Идёт разработка MVP: сдача 30.09, заморозка кода 29.09 днём. **Текущее состояние и следующий шаг — в `hack-docs/HANDOFF.md`.**

## Две документации (ADR-001) и сдача без ИИ-меток (ADR-007)
- `hack-docs/` — внутренняя база для команды и агентов: атомарные заметки с frontmatter. **В сдачу не входит.**
- `docs/` + `README.md` — документация продукта для жюри. Ведётся параллельно с кодом тем, кто пишет фичу, по фактическому коду; перед сдачей её вычитывают люди. Без frontmatter, wikilinks, упоминаний ИИ и агентов.
- **Коммиты — без трейлеров `Co-Authored-By: Claude …` и строк «Generated with Claude Code»** (решение команды, приоритетнее стандартной атрибуции). В коде нет комментариев «generated by».
- Сдача — отдельный чистый репозиторий: экспорт исключает `hack-docs/`, `CLAUDE.md`, `AGENTS.md`, `LEAN-CTX.md`, `PRIVET_OT_CLAUDE_FOR_DEVOPS.md`, `.claude/`, `.obsidian/`.
- Код, идентификаторы и сообщения коммитов — на английском (Conventional Commits). **Комментарии в коде (включая doc-комментарии и тесты) — на русском.** Документация — на русском.

## Продукт (ADR-002)
- **Ядро (Must):**
  - проблема описывается через бота (простой диалог) или мини-приложение (QR/диплинк; текст → LLM → форма);
  - система определяет ответственного и срок;
  - житель может нажать «это и у меня» вместо создания дубля;
  - участникам приходит живая карточка; её можно отправить в домовой чат без ПДн;
  - сотрудник УК меняет статус.
- **Should:** сроки и просрочка, PDF-эскалация в ГЖИ, черновик обращения через LLM, дашборд метрик УК.
- **Could — только после «ворот экосистемы» 22.09** (ядро e2e на mobile и web): совет дома, приём в УК, модерация канала, опросы без юридической силы.
- **Won't Have:** оплата и показания, верификация собственности, юридически значимое ОСС (463-ФЗ), массовые рассылки.
- **Контекст:** сегмент — жители панельного фонда 70–90-х; пилот — Москва, один район; модель — B2G-пилот → SaaS для УК.
- **Тон текстов:** строгость Госуслуг + дружелюбие соседа.

## Архитектура (ADR-003, ADR-010, ADR-011)
```
backend/                Go 1.27.1 · Fiber v3 · pgx + sqlc · PostgreSQL · goose
  cmd/api/              точка сборки: конфиг, зависимости, HTTP, бот, фоновые задачи
  internal/domain/      ядро DDD-lite без внешних зависимостей: issue (агрегат), house, user, rules
  internal/app/         сценарии + порты (интерфейсы); зависит только от domain
  internal/app/apptest/ хранилище в памяти для юнит-тестов сценариев
  internal/transport/   входящие: httpapi (Fiber), bot (события MAX, webhook, polling), jobs (outbox, просрочки)
  internal/storage/     исходящие: postgres (репозитории, migrations, queries → sqlcdb), maxapi (клиент Bot API)
miniapp/                Vite · React 19 · TypeScript (strict) · @maxhub/max-ui · MAX Bridge · Vitest
  src/app (сессия, стек экранов), src/pages, src/shared/{api,bridge,lib,ui,theme}
deploy/                 compose.yaml, Caddyfile, seed/
api/openapi.yaml        контракт OpenAPI 3.1, пишется руками (ADR-006)
DATA-API.yaml           обязательные проверки собственного API
docs/                   документация продукта (ведётся вместе с кодом)
```
- **Слои:**
  - `domain` ни от чего не зависит;
  - `app` зависит только от `domain`;
  - `transport` и `storage` зависят от `app` и `domain`;
  - сборка зависимостей — только в `cmd/api`.
- **YAGNI** (список в ADR-010): без CQRS, шины событий и DTO на каждый сценарий; LLM, MinIO и PDF подключаются позже, как Should.
- **Go:** версия 1.27.1. Перед правкой Go-файла — скилл `modern-go-guidelines:use-modern-go` (`list --go-version 1.27`), после правок — диагностика gopls.
- **Бот:** свой тонкий клиент `internal/storage/maxapi` (около 6 методов). SDK `max-bot-api-client-go` — только если он поддерживает `platform-api2` без обходных путей.
- **LLM:** Ollama self-hosted, профиль compose `llm` (ADR-008).
- **Auth:** `initData` → HMAC + TTL → сессия; демо-роли через `POST /api/v1/auth/demo` при `DEMO_AUTH_ENABLED=true` (ADR-004).
- **Хостинг:** российский VPS + Caddy TLS (ADR-005).

## Команды
**Добавляйте сюда реальные команды сразу, как только они заработают.** Не вписывайте непроверенные команды.

Единая точка — `Taskfile.yml` в корне (Task v3; `task` показывает список). Переменные для локального запуска лежат в `.env` в корне. Новые команды добавляются в Taskfile.
- `task db` — поднять Postgres 18.6 в Docker (Docker Desktop должен быть запущен);
- `task test` — юнит-тесты; `task test:integration` — тесты на Postgres (временная база на каждый прогон);
- `task lint` — `gofmt` и `go vet`;
- `task run` — api на `:8080`, миграции при старте; бот по `BOT_MODE` из `.env` (локально `off`);
- `task test:live` — проверка на живом MAX Bot API;
- `task sqlc` — перегенерировать код запросов после правки `queries/*.sql` или миграций;
- `task up` / `task down` / `task logs -- api` — весь стек в compose;
- `task miniapp:install` — зависимости мини-приложения (`npm ci`);
- `task miniapp:dev` — мини-приложение на `:5173`, `/api` проксируется на `task run`; открыть `http://localhost:5173/?demo=resident` (`resident_2`, `uk`), тема `&theme=dark`;
- `task miniapp:test` / `task miniapp:typecheck` / `task miniapp:build` — Vitest, TypeScript, сборка в `miniapp/dist`;
- превью для агента: `.claude/launch.json`, конфигурации `api` и `miniapp`.

## Ловушки платформы MAX
- Bot API — только `https://platform-api2.max.ru` с заголовком `Authorization: <token>`; в образе `api` нужен корневой сертификат Минцифры.
- Webhook — только HTTPS:443 с доверенным CA; ответ 200 ≤ 30 с (у нас ≤ 1 с, обработка асинхронная); события дублируются → дедупликация `processed_updates`; секрет в `X-Max-Bot-Api-Secret`.
- **При активной подписке webhook long polling не работает** (dev-max `POST /subscriptions`) → после деплоя с `BOT_MODE=webhook` локально только `BOT_MODE=off`.
- **Любая правка настроек бота (URL мини-приложения, группы) модерируется до 48 рабочих часов** — URL стабильный, меняется только код за ним.
- Лимиты: 30 rps глобально, 2 rps на чат для send/edit/delete/answers → все отправки только через outbox.
- `initDataUnsafe` не доверять; телефон — только `requestContact` с проверкой hash.
- На web не работают `DeviceStorage`, `SecureStorage`, `HapticFeedback`, `shareContent` → у каждой функции Bridge должен быть запасной путь.
- В MAX UI нет модалок, табов, select, toast, checkbox, stepper и загрузки файлов → свои компоненты в `miniapp/src/shared/ui/` (лист — нативный `<dialog>`, тост — `popover`).
- `@maxhub/max-ui` 0.5.0 расходится с документацией: пропс `variant` вместо `mode`, нет Panel/Container/Flex/Grid/SearchInput, есть Radio; peer — ровно React 19.2.8. Смотреть типы в `node_modules/@maxhub/max-ui/dist/components`.
- Вне MAX скрипт Bridge не имеет транспорта: вызовы `BackButton` и т.п. делать только при `bridge.inMax()`.
- Диплинки: `?start=` ≤ 128 символов, `?startapp=` ≤ 512 символов `[A-Za-z0-9_-]`; в payload только непрозрачные id.
- `GET /chats` удалён, `POST /chats/{id}/members` удаляется 30.09.2026 — не использовать.
- Требования MAX §1.5: без массовых и сервисных рассылок → уведомляем только участников их заявок.
- Сообщение с inline-клавиатурой в диалоге редактируется бессрочно → на этом построена живая карточка (`PUT /messages`).

## Как работаем
- **Процесс (superpowers):** brainstorming → writing-plans → test-driven-development → verification-before-completion; перед слиянием — requesting-code-review.
- **Go:** перед правкой вызвать skill `modern-go-guidelines:use-modern-go` (`list --file-path <файл>`) и следовать выданным правилам.
- **Фронт (HTML/CSS/JS):** сначала skill `modern-web-guidance:modern-web-guidance`.
- **Документация библиотек** (Fiber v3, sqlc, MAX UI, Vite…) — через context7, не по памяти.
- **Файлы и поиск** — инструменты lean-ctx (`ctx_read`, `ctx_search`, `ctx_shell`, `ctx_compose`); см. `LEAN-CTX.md`.
- **Контракт до кода:** правки `api/openapi.yaml` — отдельным PR с ревью обеих пар.
- **Код агентов (Gemini и др.):** PR принимает человек из пары, который может объяснить код (п. 9.5 правил).
- **LLM в продукте только подсказывает:** категория — из закрытого списка; ответственный и срок — из правил; нормы — из справочника; без LLM всё работает.
- **Definition of Done фичи:** тесты; состояния загрузки, ошибки и «пусто»; раздел в `docs/`; FR отмечены в Issue.
