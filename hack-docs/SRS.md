## 1. Введение

### 1.1 Назначение
Требования к MVP чат-бота и мини-приложения в MAX для трека «Умный город» (кейс «Умный дом»): коллективные заявки о неисправностях общего имущества МКД.

### 1.2 Область
- **В рамках:** ядро из [ADR-002](adr/002-product-scope.md) — сообщение о проблеме (бот или мини-приложение), определение ответственного и срока, присоединение вместо дубля, живая карточка, шеринг без ПДн, обработка сотрудником УК; Should — сроки и просрочка, PDF-эскалация, черновик обращения, дашборд метрик.
- **За воротами экосистемы (Could, после 22.09):** совет дома, приём в УК, модерация канала, опросы без юридической силы, собственный домовой чат, 60+.
- **Вне рамок:** оплата и показания, верификация собственности, юридически значимое ОСС, массовые рассылки.

### 1.3 Термины
| Термин | Значение |
|---|---|
| МКД | многоквартирный дом |
| Общее имущество | лифты, подъезды, кровля, инженерные системы, придомовая территория (ЖК РФ ст. 36) |
| УК | управляющая организация (в роли УК может быть ТСЖ или ЖСК) |
| РСО | ресурсоснабжающая организация |
| АДС | аварийно-диспетчерская служба |
| ГЖИ | государственная жилищная инспекция (в Москве — Мосжилинспекция) |
| Проблема (Issue) | неисправность общего имущества, к которой присоединяются жители |
| Участник | житель, создавший проблему или присоединившийся к ней |
| Живая карточка | сообщение бота с inline-кнопками, которое редактируется при смене статуса |
| Ворота экосистемы | условие 22.09: основной сценарий проходит e2e на mobile и web |

## 2. Общее описание

### 2.1 Позиционирование
Надстройка над официальными каналами (прежде всего «Госуслуги.Дом»): коллективный слой, который превращает хаос сообщений в домовом чате в одну доказательную заявку с понятным ответственным и сроком ([competitors](research/competitors.md)). **Пилот:** Москва, один район панельной застройки. **Модель:** B2G-пилот → SaaS для УК.

### 2.2 Компоненты
| Компонент | Технологии | Роль |
|---|---|---|
| Чат-бот MAX | Bot API через `max-bot-api-client-go` | вход, простые заявки диалогом, живые карточки, уведомления участникам |
| Мини-приложение | Vite + React (JavaScript) + MAX UI + MAX Bridge | формы, списки, фото, роль УК и дашборд, шеринг, PDF |
| Бэкенд | Go, Fiber v3, pgx + sqlc | домен, API `/api/v1`, webhook, outbox, таймеры сроков, PDF |
| БД | PostgreSQL | данные и события |
| Хранилище файлов | MinIO (S3) | фото и PDF |
| LLM | Ollama (self-hosted, открытая модель) | классификация и черновик, с откатом на правила |
| Прокси | Caddy | TLS, маршрутизация |

Архитектура: [ADR-003](adr/003-backend-architecture.md). Хостинг: [ADR-005](adr/005-hosting-https.md).

### 2.3 Среда
Клиенты MAX: iOS, Android, desktop, **web — обязательно**. Российский VPS; HTTPS 443; доверенный сертификат Минцифры для запросов к `platform-api2.max.ru`.

### 2.4 Допущения
- A1. Адреса и УК — открытые данные Москвы одного района; объекты, жители и заявки — синтетические с маркировкой ([data-model](requirements/data-model.md)).
- A2. Роль УК в демо выполняет тестовая учётка `uk_operator_demo`.
- A3. Заявка в продукте не является официальным обращением по ПП 416, пока нет интеграции с ГИС ЖКХ или соглашения с УК; в интерфейсе указан официальный канал.
- A4. Проблема подтверждается аргументированными допущениями и открытыми данными, без полевых интервью (решение команды).
- A5. Бот и токен предоставляются организаторами (**токен ещё не выдан**).

## 3. Роли

| Роль | Права | Приоритет |
|---|---|---|
| `resident` Житель | привязка к дому; создание и присоединение; проблемы своего дома без чужих ПДн; шеринг; PDF; удаление своих данных | Must |
| `uk_operator` Сотрудник УК | проблемы домов своей организации; смена статуса с комментарием; дашборд метрик | Must |
| `chairman` Председатель совета | реестр проблем дома, опрос без юридической силы | Could |
| `contractor` Подрядчик | назначенные проблемы, отметка выполнения с фото | Could |
| `admin` Администратор | справочники, роли | служебная |

Видимость: соседи видят только счётчик участников; телефон виден УК, только если житель им поделился. Детали: [ADR-004](adr/004-auth-and-roles.md).

## 11. Ограничения
- **Платформа:** модерация настроек бота до 48 рабочих часов; лимиты API; нет компонентов в MAX UI; ограничения Bridge на web; нет API опросов и рассылок.
- **Данные:** нет доступа к API ГИС ЖКХ и ЕСИА; интеграции модельные и помечены.
- **LLM:** качество компактных моделей и задержка на CPU.
