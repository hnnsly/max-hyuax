### Итоги ревью и UX-прохода (24.09)
- **Фото:**
  - на телефоне снимок ужимается до 1600 px и перекодируется в JPEG до отправки: снимки камер больше 5 МБ проходят;
  - на сервере предел по памяти считается с глубиной цвета, одновременно декодируются не больше двух снимков, поворот идёт после уменьшения;
  - пачка файлов сохраняется целиком или не сохраняется, лимит 6 пересчитывается под блокировкой заявки;
  - житель прикладывает фото только с согласием; своё фото можно убрать (`DELETE /photos/{id}`);
  - бот берёт альбом целиком (до 3 снимков), ссылка на снимок не попадает в логи.
- **Удаление аккаунта:** стирает дом и связь с MAX, удаляет фото пользователя. Вернувшийся житель получает новый аккаунт без старых заявок. Демо-пользователь возвращается в исходное состояние, поэтому DATA-API проходит и после шага удаления.
- **Прочее:**
  - id не uuid в адресе даёт 404 вместо 500;
  - ссылка на PDF-обращение перепроверяет заявку и владельца;
  - просрочка в хронологии стоит на моменте срока;
  - пакет просрочек не останавливается на сбойной заявке;
  - сдвиг примера данных идёт под advisory lock;
  - прогрев модели сдаётся после 30 попыток.
- **Мини-приложение:**
  - PDF в MAX скачивается в два нажатия: `downloadFile` требует свежего клика (dev-max/docs/webapps/bridge.md);
  - печать наклейки даёт ровно один лист A6, на телефонах кнопки печати нет;
  - «Повторить» на экране ошибки входа;
  - просроченные заявки первыми на «Моём доме»;
  - панель кнопок поверх точек хронологии; поиск дома без гонки ответов;
  - лист удаления не закрывается во время запроса.
- **Проверить людям в MAX:** скачивание PDF в два нажатия; работает ли `<input type=file>` в WebView MAX; печать наклейки из MAX на компьютере. Если печать не работает, нужен PDF наклейки с сервера.

## Как запустить
Всё через `task` (список: `task`), переменные — из `.env` в корне.
```bash
task db                 # Postgres в Docker
task test               # юнит-тесты
task test:integration   # тесты на Postgres
task run                # api на :8080, миграции при старте, BOT_MODE=off
task miniapp:dev        # мини-приложение на :5173, /?demo=resident | resident_2 | uk
```
Как у жюри, одной командой: `docker compose -f deploy/compose.yaml --env-file deploy/.env.example up -d --build`, затем `http://localhost/?demo=resident`.

## Известные проблемы
- **Превью агента.** Если `:8080` занят (зависший `go run`), запускать `api-8081` и `miniapp-8081` из `.claude/launch.json`: прокси Vite берёт адрес из `API_PROXY`.
- **Vite на Windows не видит правки через `sed -i`.** Модуль остаётся старым, поэтому файлы `miniapp/src` правятся только через редактор.
- **Кириллица в `curl` из консоли Windows** уходит в cp1251, и API отвечает 422. Тело нужно брать из файла в UTF-8: `--data-binary @file.json`.
- **Webhook и polling.** После включения webhook на сервере long polling перестаёт работать у всех: локально держать `BOT_MODE=off`.
- **Документация `Update` в `dev-max/`** описывает только `bot_added`. Поля `bot_started` и `message_callback` взяты из `POST /answers`, первые реальные события нужно сверить в логах.
- **Сроки в `rules`** модельные, праздники не учитываются (записано в `docs/data.md`).
- **Git предупреждает про LF → CRLF.** Не мешает.
