## Как запустить
Всё через `task` (список: `task`), переменные — из `.env` в корне.
```bash
task db                 # Postgres в Docker
task s3                 # MinIO в Docker (фото; нужен для test:integration)
task test               # юнит-тесты
task test:integration   # тесты на Postgres
task run                # api на :8080, миграции при старте, BOT_MODE=off
task miniapp:dev        # мини-приложение на :5173, /?demo=resident | resident_2 | chairman | uk | district
task import:houses -- deploy/seed/houses-sample.csv   # реестр домов из CSV
```
Как у жюри, одной командой: `docker compose -f deploy/compose.yaml --env-file deploy/.env.example up -d --build`, затем `http://localhost/?demo=resident`.

## Известные проблемы
- **Превью агента.** Если `:8080` занят (зависший `go run`), запускать `api-8081` и `miniapp-8081` из `.claude/launch.json`: прокси Vite берёт адрес из `API_PROXY`.
- **Vite на Windows не видит правки через `sed -i`.** Модуль остаётся старым, поэтому файлы `miniapp/src` правятся только через редактор.
- **Кириллица в `curl --data-urlencode`** тоже уходит в cp1251: для проверок геокодера запросы собирать в скрипте на Python или Go.
- **Кириллица в `curl` из консоли Windows** уходит в cp1251, и API отвечает 422. Тело нужно брать из файла в UTF-8: `--data-binary @file.json`.
- **Локальная база и команда жюри делят том `dom-max_pg_data`.** Если база создана `task db` (пароль `dommax` из `.env`), то `up` с `deploy/.env.example` (пароль `dommax-local`) не пустит api в базу. Запускать с `POSTGRES_PASSWORD=dommax` или начать с `down -v`.
- **Webhook и polling.** После включения webhook на сервере long polling перестаёт работать у всех: локально держать `BOT_MODE=off`.
- **Документация `Update` в `dev-max/`** описывает только `bot_added`. Поля `bot_started` и `message_callback` взяты из `POST /answers`, первые реальные события нужно сверить в логах.
- **Сроки в `rules`** модельные, праздники не учитываются (записано в `docs/data.md`).
- **Git предупреждает про LF → CRLF.** Не мешает.
