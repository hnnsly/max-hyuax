## Открытые вопросы и риски
- **Смена роли и ПДн.** `/role` и `POST /me/role` сейчас работают у любого пользователя. Житель, ставший «сотрудником УК», видит телефоны и имена соседей. Исправляется шагом 3 GEN_V3: только в демо-режиме, переключённая роль видит контакты только демо-жителей.
- **Атрибуция OSM.** Подпись «© участники OpenStreetMap» убрана из интерфейса (`5674650`), а ODbL её требует (ADR-016). Возвращается мелкой строкой внизу экранов (шаг 3).
- **Геопозиция в мини-приложении.** В WebView MAX нет `navigator.geolocation`, в Bridge геолокации нет. «Найти дома рядом» не работает, решается через бота (шаг 4).
- **Бот.** Каждое нажатие присылает новое сообщение, меню приходится искать выше. Решается «одним окном» (шаг 5).

## Проверить людям в MAX
- **Демо-вход на стенде:** `DEMO_AUTH_ENABLED=true` на сервере (в `deploy/ansible/vault.yml`, файл зашифрован). Без этого не работают ссылки `?demo=` и проверки `DATA-API.yaml`.
- **Телефон в мини-приложении:** кодировка `hash` и единицы `authDate` у `requestContact` не описаны. Сервер принимает hex в любом регистре, секунды и миллисекунды. При 422 `invalid_contact` смотреть, что вернул клиент.
- **Телефон в боте:** кнопка `request_contact`, подпись `HMAC-SHA256(vcf_info, токен)`. Сервер принимает hex и base64; проверить, что номер сохраняется.
- **Уведомления бота:**
  - «принята» и «в работе» приходят отдельным сообщением;
  - председателю приходит новое предложение, автору — ответ.
- **Прочее:**
  - PDF скачивается в два нажатия (`downloadFile` требует свежего клика);
  - работает ли `<input type=file>` в WebView MAX;
  - печать наклейки на компьютере.

## Как запустить
Всё через `task` (список: `task`), переменные — из `.env` в корне.
```bash
task db                 # Postgres в Docker
task s3                 # MinIO в Docker (фото; нужен для test:integration)
task test               # юнит-тесты
task test:integration   # тесты на Postgres
task run                # api на :8080, миграции при старте, BOT_MODE=off
task miniapp:dev        # мини-приложение на :5173, /?demo=resident | resident_2 | chairman | uk | district
task import:houses -- deploy/seed/houses-sample.csv   # реестр домов из CSV
task export             # чистый репозиторий для сдачи (ADR-007)
```
Как у жюри, одной командой: `docker compose -f deploy/compose.yaml --env-file deploy/.env.example up -d --build`, затем `http://localhost/?demo=resident`.

## Известные проблемы
- **Превью агента.** Если `:8080` занят (зависший `api.exe`), запускать `api-8081` и `miniapp-8081` из `.claude/launch.json`: прокси Vite берёт адрес из `API_PROXY`.
- **Vite на Windows теряет перезаписанные файлы.** Файлы `miniapp/src` правятся только редактором. После массовых правок скриптом dev-сервер нужно перезапустить.
- **CRLF в рабочей копии.** После `git pull` Go-файлы коллеги приходят с CRLF, и `gofmt -l` помечает их локально. В репозитории у них LF; `gofmt -w` лечит, diff не появляется.
- **Кириллица в `curl`** из консоли Windows уходит в cp1251, в том числе через `--data-urlencode`. Тела и запросы собирать в файле UTF-8 или скрипте на Python или Go.
- **Локальная база и команда жюри делят том `dom-max_pg_data`.** Если база создана `task db` (пароль `dommax`), то `up` с `deploy/.env.example` (пароль `dommax-local`) не пустит api. Запускать с `POSTGRES_PASSWORD=dommax` или начать с `down -v`.
- **Webhook и polling.** На стенде включён webhook, поэтому long polling не работает ни у кого. Локально держать `BOT_MODE=off`.
- **Документация `Update` в `dev-max/`** описывает только `bot_added`. Поля `bot_started` и `message_callback` взяты из `POST /answers`, реальные события сверять в логах.
