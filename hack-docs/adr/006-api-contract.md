# ADR-006: Contract-first OpenAPI и объявленное собственное API

## Контекст
- Параллельная работа пар и агентов требует общего контракта до кода ([R17](../research/risks.md)).
- Команда объявляет бэкенд собственным API для проверки ([Блок В](../interview/BLOCK-V.md)). Это обязывает к HTTPS-адресу, `openapi.yaml`, тестовым учёткам ролей, тестовым данным и `DATA-API.yaml` с обязательными проверками ([Case.md](../Case.md)).
- Критерий «Корректность интеграций» (20% техники): статус-коды, форматы, заголовки и обязательные поля должны соответствовать контракту.
- Мини-приложение пишется на JavaScript, поэтому генерируемых типов на фронте нет.

## Решение
1. **OpenAPI 3.1** — единственный источник контракта: `api/openapi.yaml`. Контракт меняется только через PR, ревью обеих пар обязательно.
2. **Бэкенд:** валидация запросов и ответов по OpenAPI в тестах (контрактные тесты); хендлеры на Fiber — генерация через oapi-codegen или ручные хендлеры (решает пара в Спайке 0 после проверки поддержки Fiber v3), соответствие в любом случае проверяют тесты.
3. **Фронт (JS):** тонкий fetch-клиент `miniapp/src/api/`; JSDoc-описания объектов API; единая обработка ошибок формата `{"error": {"code", "message"}}`.
4. **Единый формат ошибок** и коды: 400 валидация, 401 нет сессии, 403 нет прав, 404, 409 конфликт (например, повторное присоединение), 422 бизнес-правило, 429, 5xx.
5. **Идемпотентность** создающих запросов: заголовок `Idempotency-Key` для `POST /issues` и `POST /issues/{id}/join`.
6. **DATA-API.yaml:** 6–10 обязательных проверок основного сценария (вход демо-роли → поиск дома → создание или присоединение → карточка → смена статуса ролью УК → чтение метрик), только стабильные методы. Проверки прогоняются в CI против демо-стенда.
7. **Версионирование:** префикс `/api/v1`.

## Рассмотренные альтернативы
| Вариант | Почему не выбран |
|---|---|
| Не объявлять API | решение команды — объявляем; мини-приложение и так работает через API |
| Code-first (генерация спецификации из кода) | контракт появляется поздно, пары блокируют друг друга |
| GraphQL | избыточно, сложнее описать в DATA-API.yaml |

## Последствия
- **Плюсы:** пары работают параллельно; проверка интеграций автоматизирована; готовая документация для `docs/api.md`.
- **Минусы:** дисциплина изменения контракта; на JS-фронте нет статической проверки типов ([R24](../research/risks.md)).
- **Задачи:** черновик `openapi.yaml` к утру 18.09; схема формата `DATA-API.yaml` уточняется у организаторов; контрактные тесты в CI.

## Связанные требования
Все FR с API-взаимодействием; NFR-04, NFR-06, SEC-06 ([nfr](../requirements/nfr.md)).
