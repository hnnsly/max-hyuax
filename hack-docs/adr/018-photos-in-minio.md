# ADR-018: Фото в MinIO по S3 API

## Контекст
ADR-015 положил фото к заявкам на том Docker за портом `FileStore`, отложив MinIO из ADR-003. Команда решила вернуть настоящее объектное хранилище: так фото переживают перенос api на другую машину, хранилище масштабируется отдельно, а для пилота его можно заменить облачным S3 в РФ.

Что выяснилось про MinIO (веб-поиск 25.09.2026):
- с октября 2025 MinIO не публикует бесплатные образы; репозиторий `minio/minio` на Docker Hub уже недоступен (`not found`), исходники архивированы в апреле 2026;
- лицензия сервера AGPL-3.0;
- альтернативы с Apache-2.0 (SeaweedFS, RustFS) команда рассмотрела, но выбрала MinIO как самый узнаваемый вариант.

## Решение
- **Сервис `minio`** в `deploy/compose.yaml`:
  - образ `coollabsio/minio:RELEASE.2025-10-15T17-29-55Z` (сборка из исходников от проекта Coolify, в ней исправление безопасности октября 2025), тег закреплён;
  - том `minio_data`, healthcheck `mc ready local`;
  - S3 API и консоль открыты только на `127.0.0.1` (для `task s3` и отладки); api ходит в `minio:9000` внутри сети compose.
- **Адаптер `internal/storage/files/S3`** на `minio-go/v7` (Apache-2.0) реализует тот же порт `FileStore`:
  - бакет создаётся при старте, ошибка доступа видна сразу;
  - ключ объекта — id фото, та же проверка ключа, что у диска;
  - общий контрактный тест для диска и S3, S3-вариант идёт на настоящем MinIO в `task test:integration` и в CI.
- **Диск остаётся запасным:** без `S3_ENDPOINT` api пишет фото в `PHOTOS_DIR`. Это нужно для `task run` без Docker.
- **Лицензии:** MinIO — отдельный процесс, с которым api говорит по сети через стандартный S3 API. Наш код MinIO не включает и не меняет, поэтому AGPL на него не распространяется. Клиент `minio-go` — Apache-2.0.

## Рассмотренные альтернативы
| Вариант | Почему не выбран |
|---|---|
| Оставить том (ADR-015) | Команда хочет настоящее объектное хранилище, как в ADR-003 |
| SeaweedFS (Apache-2.0) | Зрелый, но команда выбрала MinIO; адаптер S3 позволит перейти без правок кода |
| RustFS (Apache-2.0) | Альфа-версия |
| `chainguard/minio` | Бесплатно только тег `latest`: сборку у жюри нельзя закрепить; нет `mc` для healthcheck |
| AWS SDK Go v2 | Тяжелее `minio-go` для трёх вызовов |

## Последствия
- **Плюсы:** фото отделены от api; для пилота MinIO меняется на Yandex Object Storage или VK Cloud заменой `S3_ENDPOINT`, ключей и `S3_USE_SSL`.
- **Минусы и риски:**
  - образ стороннего сборщика и без обновлений: на сервере порты MinIO наружу не открывать;
  - api использует root-ключи MinIO; для пилота завести отдельного пользователя с доступом к одному бакету;
  - стенд ещё не развёрнут, поэтому переносить фото с тома не нужно.
- **Задачи:** DevOps задаёт `MINIO_ROOT_USER` и `MINIO_ROOT_PASSWORD` в `deploy/.env`, резервная копия тома `minio_data`.

## Связанные требования
FR фото к заявке, NFR-хранение в РФ, ADR-003, ADR-015.
