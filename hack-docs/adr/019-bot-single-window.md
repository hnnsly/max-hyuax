# ADR-019: Бот 2.0 — одно окно, меню по роли, заявка кнопками, УК в чате

## Контекст
Замечания Максима после проверки в MAX (26.09):
- у бота мало функций;
- кнопки «уезжают»: каждое нажатие присылало новое сообщение, меню приходилось искать, листая чат вверх.

План — [GEN_V3_PLAN](../GEN_V3_PLAN.md), часть 5.

Платформа это позволяет:
- ответ на нажатие (`POST /answers`) может заменить сообщение с кнопкой новым текстом и клавиатурой. Живая карточка на этом уже работает: сообщение с inline-клавиатурой в диалоге редактируется бессрочно;
- в заменяющем сообщении допустимы кнопки `request_geo_location` и `request_contact`: [PUT /messages](../dev-max/docs-api/methods/PUT/messages/index.md), ограничение до 3 таких кнопок в ряду.

## Решение
- **Одно окно.** Навигация (меню, списки, карточка заявки, совет дома, «Назад») заменяет сообщение, в котором нажата кнопка.
  - Экран — функция `(ctx, user, arg) → NewMessage` в `transport/bot/screens.go`.
  - Данные кнопки — `w:<экран>:<аргументы>`, в пределах 1000 символов payload.
  - На каждом экране «Меню», на вложенных ещё «Назад».
- **Новые сообщения** бот шлёт только там, где нужен звук уведомления:
  - ответ на текст;
  - команда;
  - уведомления.

  У таких сообщений в конце кнопка «Меню». В уведомлениях и живой карточке «Меню» и «Подробнее» (`m:`, `i:`) присылают экран новым сообщением, чтобы не затереть уведомление и не сломать обновление живой карточки.
- **Меню по роли:**
  - житель;
  - председатель: плюс «Папка предложений» и «Создать опрос»;
  - сотрудник УК: «Очередь заявок», «Метрики»;
  - управа района: «Сводка района», «Просрочено в районе».

  На демо-стенде в меню есть «Роль для проверки».
- **Заявка кнопками:** категория → подъезд (если объектов больше одного) → описание следующим сообщением или «Отправить без описания». Описание ждёт в `bot_pending` (`describe`, Ref — категория, Text — объект). Путь одной фразой сохранён.
- **Смена статуса УК в чате:**
  - кнопки строятся из `issue.NextStatuses` (переходы агрегата);
  - «Выполнено» спрашивает комментарий, есть «Без комментария»; «Отклонить» требует причину (`bot_pending` `status`);
  - права и переход проверяются до вопроса, чтобы бот не просил текст, который не примет.
- **Ожидание текста снимается** любым переходом на экран или командой: после «Назад» следующий текст снова считается проблемой.

## Рассмотренные альтернативы
| Вариант | Почему не выбран |
|---|---|
| Удалять старое меню и присылать новое | Лишние вызовы `DELETE` при лимите 2 rps на чат, мигание сообщений |
| Меню только в мини-приложении | Замечание как раз про бот: многие жители не открывают мини-приложение |
| Хранить текущий экран на сервере | Состояние в данных кнопки проще и переживает перезапуск; `bot_pending` нужен только для текста |

## Последствия
- **Плюсы:**
  - чат не засоряется;
  - бот закрывает все роли без мини-приложения;
  - сотрудник УК может работать с телефона прямо в чате.
- **Минусы и риски:**
  - экран в заменённом сообщении не обновляется сам: статус в старом экране может устареть до следующего нажатия;
  - звук уведомления есть только у новых сообщений.
- **Проверить людям в MAX:** замена сообщения с кнопкой геопозиции; поведение «Назад» на iOS, Android и в web.
- **Исправлено попутно:** вопрос нового опроса председателя раньше уходил в «новую проблему» (`new_poll` не был в `onPending`).
