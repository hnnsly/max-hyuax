# ADR-013: Локальный запуск для жюри и формат DATA-API.yaml

## Контекст
- [Case.md](../Case.md) требует одну команду Docker для всех локальных компонентов, `.env.example` без рабочих секретов, сборку не дольше 5 минут и `DATA-API.yaml` с обязательными проверками (пункты a–i).
- Официальной схемы `DATA-API.yaml` у организаторов нет ([ADR-006](006-api-contract.md): «схема уточняется»).
- `deploy/compose.yaml` уже используется DevOps для сервера и `task db` для разработки.

## Решение
1. **Один compose для всех.**
   - `deploy/.env.example` содержит рабочие локальные значения: `DOMAIN=:80` (Caddy по HTTP), демо-вход включён, бот выключен, пароль и секрет помечены «только для локального запуска».
   - Команда запуска: `docker compose -f deploy/compose.yaml --env-file deploy/.env.example up -d --build`. Сервер использует `deploy/.env`.
   - Порты вынесены в `HTTP_PORT`, `HTTPS_PORT`, `DB_PORT`. Локально база на `127.0.0.1:15432`, чтобы не спорить с Postgres жюри.
2. **Свой формат `DATA-API.yaml` версии `1.0`.**
   - Поля: `solution`, `base_url`, `auth` (демо-вход и роли), `checks[]` с `method`, `path`, `role`, `params` (`path`, `query`, `headers`, `body`) и `expect` (`status[]`, `content_type`, `body`, `required_fields`).
   - Для неидемпотентных шагов проверки допускают несколько кодов (`[200, 409]`) и отдельные обязательные поля на каждый код.
3. **Проверка в CI.** Integration-тест `httpapi/dataapi_test.go`:
   - прогоняет каждую проверку против настоящего API на временной базе;
   - сверяет, что путь и метод есть в `api/openapi.yaml`.

## Рассмотренные альтернативы
| Вариант | Почему не выбран |
|---|---|
| Отдельный `compose.local.yaml` | два файла расходятся; DevOps и жюри запускали бы разное |
| Пустой `.env.example` + инструкция «заполните» | лишний шаг для жюри, риск ошибки в секрете короче 16 символов |
| Проверка DATA-API скриптом вне тестов | без CI файл тихо разойдётся с API |

## Последствия
- **Плюсы:**
  - сборка с нуля занимает 129 с, запуск 20 с (замер 24.09);
  - данные переживают `down` и `up`;
  - DATA-API и контракт проверяются на каждый push.
- **Минусы и риски:**
  - если организаторы пришлют свою схему DATA-API, файл нужно будет переложить;
  - в `base_url` метка `<домен-стенда>`, её нужно заменить перед сдачей.
- **Задачи:** заменить `<домен-стенда>` в README, `DATA-API.yaml`, `docs/`, `deploy/seed/test-data.json`, когда DevOps поднимет стенд.
