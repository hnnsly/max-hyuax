# ADR-012: Taskfile.yml — единая точка команд проекта

## Контекст
- Команды разрознены: `go test` с тегами и переменными, `docker compose -f deploy/compose.yaml`, `go tool sqlc`. Каждый новый участник (или агент в новой сессии) восстанавливает их заново.
- Среда смешанная: Windows (Git Bash, PowerShell) у разработчиков, Linux на VPS и в CI.
- Решение пользователя от 24.09: «теперь мы ведём Taskfile.yml для удобного управления проектом».

## Решение
- **`Taskfile.yml` в корне** (Task v3). Каждая задача с `desc`, `task` без аргументов показывает список.
- **Переменные для локального запуска** — `.env` в корне, подключается через `dotenv`. На сервере compose читает `deploy/.env`.
- **Раздел «Команды» в `CLAUDE.md`** описывает задачи Taskfile, а не сырые команды. Новая команда сначала появляется в Taskfile.
- **Разрушительные задачи** (`db:reset`) спрашивают подтверждение через `prompt`.

## Рассмотренные альтернативы
| Вариант | Почему не выбран |
|---|---|
| Makefile | нет `make` в Windows из коробки, хуже с кроссплатформенными командами |
| npm scripts | бэкенд на Go, Node нужен только мини-приложению |
| Команды только в документации | копируются с ошибками, расходятся с реальностью |

## Последствия
- **Плюсы:** одна команда на действие, одинаково в Windows, Linux и CI; агенту не нужно выводить команды заново.
- **Минусы:** нужен установленный `task` (у команды есть; в CI вызываются прямые команды).
