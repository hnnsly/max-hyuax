# ADR-001: Разделение рабочей базы знаний и документации продукта

## Контекст
- Над проектом работают 4 человека, 5 Gemini-агентов и Claude Code. Контекст агентов теряется, поэтому нужна подробная атомарная база знаний: ресерч, SRS, план, ADR, интервью.
- Жюри оценивает техническую документацию (10% технической оценки): README из 14 разделов, описание API, данных, запуска и ограничений ([Case.md](../Case.md)).
- Правила хакатона: п. 9.5 запрещает ИИ «в виде окончательного решения»; п. 11.3 запрещает передавать задание третьим лицам. `Case.md` и правила уже лежат в истории git ([risks](../research/risks.md), R7 и R8).
- Команда не хочет сдавать массив служебных markdown-файлов для агентов и какие-либо ИИ-метки.

## Решение
1. Исходные материалы и вся внутренняя база знаний лежат в `hack-docs/` (бывшая `docs/`, переименована через `git mv`). В сдачу не входит.
2. `docs/` и `README.md` в корне — документация продукта для жюри и пользователей. Пишется людьми по фактическому коду, без frontmatter, wikilinks и упоминаний ИИ.
3. Правило «без ИИ-меток»: в сдаче нет `hack-docs/`, `CLAUDE.md`, `AGENTS.md`, `LEAN-CTX.md`, `.claude/`, `.obsidian/`; в коде нет комментариев «generated by»; в коммитах нет ИИ-трейлеров.
4. Способ упаковки сдачи выбирается отдельно ([ADR-007](README.md), Блок Г).

## Рассмотренные альтернативы
| Вариант | Плюсы | Минусы | Почему не выбран |
|---|---|---|---|
| Одна папка `docs/` для всего | проще | жюри получает служебные заметки агентов; риск п. 9.5 и п. 11.3 | противоречит требованию команды |
| База знаний вне репозитория (Notion, Google Docs) | не попадает в git | агенты теряют доступ через файловую систему; нет версионирования рядом с кодом | ухудшает работу агентов |
| `hack-docs/` в `.gitignore` | не попадает в историю | команда теряет синхронизацию и историю изменений | нужна совместная работа |

## Последствия
- Положительные: агенты получают полный контекст; жюри получает чистую документацию; снижены риски п. 9.5 и п. 11.3.
- Отрицательные: документацию продукта пишем отдельно от рабочей → закладываем время в definition of done каждой фичи и на этапе 4.
- Задачи: пути в заметках указывают на `hack-docs/`; CLAUDE.md (после интервью) описывает оба мира; перед сдачей — проверка на ИИ-метки.

## Связанные требования
SRS §10 (документация продукта и комплект сдачи).
