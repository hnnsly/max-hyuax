# ADR-008: Self-hosted LLM (Ollama) для классификации и черновиков

## Контекст
- Команда выбрала LLM для двух задач: классификация свободного описания (категория, объект, ответственный) и черновик обращения ([Блок А](../interview/BLOCK-A.md)); провайдер — self-hosted модель в Ollama ([Блок В](../interview/BLOCK-V.md)).
- Кейс требует привязывать ответы к источникам, предусматривать нехватку надёжного ответа и не выдавать предположение модели за факт ([Case.md](../Case.md)).
- п. 9.5 правил: ИИ не может быть «окончательным решением задания» → LLM — вспомогательная функция, а не суть продукта.
- Тексты жителей — ПДн: self-hosted на российском VPS исключает передачу третьим лицам.
- Сборка Docker ≤ 5 мин; модели весят гигабайты; на VPS без GPU инференс медленный.

## Решение

### Размещение
- Сервис `ollama` в compose-профиле `llm`.
- Модель скачивается при первом старте (init-скрипт), **не при сборке**.
- Кандидаты: компактные открытые instruct-модели 3–8B с пермиссивной лицензией и хорошим русским (например, семейство Qwen). Лицензию и качество на русском проверить в Спайке 0.
- В README указать требования к ресурсам и время первой загрузки.

### Роль LLM — только подсказка
1. **Классификация:** текст → структурированный JSON (категория из **закрытого списка справочника**, объект, срочность, уверенность). Невалидный JSON или уверенность ниже порога → пользователь выбирает категорию из списка вручную.
2. **Черновик обращения:** генерация по шаблону. Нормы и сроки подставляются **из нашего справочника**, а не придумываются моделью. Текст всегда редактируется и подтверждается пользователем. Метка в интерфейсе: «черновик, проверьте».
3. **Ответственный и срок** определяются **правилами** (`ResponsibilityRules`, `DeadlineRule`) по категории, которую подтвердил пользователь, а не моделью.

### Устойчивость
- Таймаут (например, 8 с на классификацию) → откат на ручной выбор.
- Сервис недоступен → продукт полностью работает без LLM.
- Вызовы асинхронные, в интерфейсе видно состояние загрузки.

### Безопасность
- В промпт не передаются телефон и имя.
- Промпт-инъекции гасятся закрытым списком категорий и схемой ответа.
- Логи не содержат текстов жителей.

### Прозрачность для жюри
Раздел в `docs/integrations.md`: модель, лицензия, что делает LLM, что делают правила, как работает откат.

## Рассмотренные альтернативы
| Вариант | Почему не выбран |
|---|---|
| GigaChat / YandexGPT | решение команды — self-hosted; внешняя зависимость от ключей |
| Gemini через OpenRouter | передача ПДн за рубеж |
| Без LLM | решение команды — нужна классификация свободного текста |

## Последствия
- **Плюсы:** быстрый ввод свободным текстом; нет передачи ПДн третьим лицам; продукт работает и без LLM.
- **Минусы и риски:** ресурсы VPS и задержка на CPU ([R20](../research/risks.md)); качество маленьких моделей на русском; время первого старта.
- **Задачи (Спайк 0):** выбрать модель, замерить p95 задержки на VPS, собрать мини-набор из 30 описаний для проверки точности классификации.

## Связанные требования
FR-LLM-01…04, NFR-09, SEC-12 ([nfr](../requirements/nfr.md)).
