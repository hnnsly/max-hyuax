# Нефункциональные требования

Вынесено из [SRS](../SRS.md) (разделы 7–9) и дополнено по итогам интервью. Решения: [ADR-003](../adr/003-backend-architecture.md), [ADR-004](../adr/004-auth-and-roles.md), [ADR-005](../adr/005-hosting-https.md), [ADR-006](../adr/006-api-contract.md), [ADR-008](../adr/008-llm-self-hosted.md).

## 1. Качество и производительность (NFR)

| ID | Требование | Проверка |
|---|---|---|
| NFR-01 | Webhook отвечает 200 не позже 1 с; обработка асинхронная; повторные события не создают дублей | интеграционный тест с повторной доставкой |
| NFR-02 | Исходящие вызовы Bot API ≤ 30 rps глобально и ≤ 2 rps на чат; ретраи с backoff; `attachment.not.ready` повторяется | юнит-тест лимитера |
| NFR-03 | Основной сценарий проходит в MAX на iOS, Android, desktop и web; недоступные функции Bridge заменяются рабочей альтернативой | ручной чек-лист на 4 клиентах |
| NFR-04 | Каждый экран и ответ бота сообщает о загрузке, успехе и ошибке; после ошибки можно продолжить без перезапуска | UX-чек-лист |
| NFR-05 | p95 ответа API ≤ 500 мс на демо-данных (без LLM) | нагрузочный прогон k6 или hey |
| NFR-06 | Повторный прогон основного сценария стабилен; создающие запросы идемпотентны (`Idempotency-Key`) | e2e дважды подряд |
| NFR-07 | Доступность: тапы ≥ 44 px, контраст по WCAG AA, понятные тексты (углублённая поддержка 60+ — Could) | ревью UI |
| NFR-08 | Логи структурированы (JSON), без ПДн, секретов и текстов жителей | ревью и grep по логам |
| NFR-09 | LLM: классификация ≤ 8 с, иначе откат на ручной выбор; продукт полностью работает без сервиса `ollama` | тест с выключенным ollama |
| NFR-10 | Время до реакции, дубли и просрочки вычисляются из событий заявок (для дашборда и слайда) | юнит-тест расчёта метрик |
| NFR-11 | Модельные и синтетические данные маркируются в интерфейсе и документации | ревью |

## 2. Безопасность и персональные данные (SEC)

| ID | Требование |
|---|---|
| SEC-01 | Секреты (токен бота, секрет webhook, ключ подписи сессий, пароли БД и MinIO) — только в переменных окружения; в репозитории `.env.example` без значений; поиск секретов в CI |
| SEC-02 | `POST /auth/max`: HMAC initData, уникальность ключей, `auth_date` ≤ 1 ч; далее сессионный токен на 12 ч |
| SEC-03 | Проверка hash у `requestContact` (Bridge) и у контакта через кнопку `request_contact` (бот) |
| SEC-04 | Webhook принимает только запросы с верным `X-Max-Bot-Api-Secret` |
| SEC-05 | RBAC на сервере; сотрудник УК видит только дома своей организации; клиенту не доверяем |
| SEC-06 | Защита от подмены и дублирования: идемпотентные ключи, rate limit на пользователя, валидация входных данных по OpenAPI |
| SEC-07 | 152-ФЗ: политика ПДн и соглашение, согласие перед первой заявкой (с версией и датой), минимизация, удаление аккаунта и обезличивание участий |
| SEC-08 | Соседи видят только счётчик участников; телефон виден УК только если житель поделился; в карточках для шеринга нет ПДн |
| SEC-09 | Payload диплинков — только непрозрачные идентификаторы (`o_<code>`, `i_<id>`) |
| SEC-10 | Файлы: проверка типа и размера, случайные ключи в MinIO, выдача по подписанным ссылкам с TTL; EXIF удаляется из фото |
| SEC-11 | `POST /auth/demo` работает только при `DEMO_AUTH_ENABLED=true` |
| SEC-12 | LLM self-hosted на российском VPS; в промпт не передаются имя и телефон; категория — только из закрытого списка; нормы в черновике — из справочника, не от модели |
| SEC-13 | Зависимости с зафиксированными версиями (`go.sum`, `package-lock.json`); CI-проверка уязвимостей (`govulncheck`, `npm audit`) |
| SEC-14 | Хранение данных в РФ (российский VPS) |

## 3. Развёртывание (DEP)

| ID | Требование |
|---|---|
| DEP-01 | `docker compose up --build` одной командой поднимает все локальные компоненты (api, miniapp, postgres, minio, caddy); LLM — профиль `llm` |
| DEP-02 | Сборка ≤ 5 минут без учёта загрузки базовых образов; модель LLM скачивается при старте, а не при сборке; время замеряется в CI |
| DEP-03 | Многоэтапные Dockerfile, `.dockerignore`, минимальные runtime-образы |
| DEP-04 | Корневой сертификат Минцифры в доверенных сертификатах образа `api` |
| DEP-05 | Прод: Caddy с TLS на 443 для статики мини-приложения, `/api/` и `/webhook/max` |
| DEP-06 | Локальный режим без публичного HTTPS: `BOT_MODE=polling`, демо-данные из seed |
| DEP-07 | Порты, переменные, зависимости, остановка и перезапуск описаны в README |
| DEP-08 | Healthcheck всех сервисов и `restart: unless-stopped`; миграции и seed выполняются автоматически при старте |
