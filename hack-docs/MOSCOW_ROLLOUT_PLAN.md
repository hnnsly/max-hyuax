> Задача: Масштабирование на всю Москву по-взрослому без раздувания базы данных и без ограничений одним районом.

## 2. Пошаговый план изменений

### Шаг 1. Расширение геокодера OpenStreetMap (`backend/internal/storage/geo/`)
- Добавить в `Nominatim` структурированный разбор адреса:
  - `City`: проверка на "Москва" (или границы BBox Москвы: `lat: 55.1..56.1, lon: 36.8..38.0`);
  - `District`: извлечение района столицы (`suburb` / `city_district`, очистка от префиксов `"район"`, `"муниципальный округ"`);
  - `Road` + `HouseNumber`: нормализованный адрес дома.
- Метод `ReverseDetails(ctx, lat, lon) (GeoHouse, ok, inMoscow, err)`: возвращает нормализованный адрес, район, флаг `inMoscow`.
- Метод `GeocodeDetails(ctx, query) ([]GeoHouse, err)`: полнотекстовый поиск домов по Москве.

### Шаг 2. Доменная логика авто-подключения домов (`backend/internal/app/houses/`)
- Реализация авто-создания районного отделения управляющей компании:
  - ID: `org-gbu-<транслит_района>`
  - Название: `ГБУ «Жилищник района <Район>»`
  - Телефон диспетчерской: `+7 (495) 539-53-53` (Единый диспетчерский центр Москвы)
  - Телефон экстренный: `+7 (495) 539-53-53`
  - График: `круглосуточно`
- Метод `ResolveByCoords(ctx, lat, lon)`:
  - Если в радиусе 150 м есть дом в БД — возвращает его.
  - Если нет, но точка в Москве — геокодирует через OpenStreetMap, находит/создаёт районный Жилищник, создаёт дом с 4 подъездами и объектами через `tx.Houses().Upsert`.
  - Если точка вне Москвы — возвращает признак `OutCity = true`.
- Метод `SearchWithFallback(ctx, query)`:
  - Ищет в БД. Если результатов < 3, дозапрашивает OpenStreetMap по Москве, авто-создаёт новые найденные дома и объединяет выдачу.

### Шаг 3. Обработка геопозиции в чат-боте (`backend/internal/transport/bot/handler.go`)
- В методе `onLocation`:
  - Вызов `ResolveByCoords(lat, lon)`.
  - Если дом найден или создан в Москве — сразу предлагает кнопку с этим реальным домом жителя.
  - Если геолокация вне Москвы — отправляет вежливый ответ:
    *«Вы находитесь за пределами Москвы. Сервис сейчас запущен по всей Москве. Вы можете выбрать один из примеров домов столицы или найти московский дом в поиске:»*
    и прикрепляет 3 образцовых дома из базы (например, Тверская, Ореховый, Ясеневая).

### Шаг 4. Уборка демо-роли района (`district`)
- Удалить роль `district` из `POST /api/v1/auth/demo` и из перечня демо-кнопок в мини-приложении (оставляем только полноценные роли: `resident`, `resident_2`, `chairman`, `uk_operator`).
- Обновить тесты аутентификации и документацию.

### Шаг 5. Тестирование и верификация
- Юнит-тесты на разбор московских адресов и районов в `geo`.
- Тесты создания домов на лету и привязки к ГБУ «Жилищник» в `houses.Service`.
- Прогон `go test ./...` и `go vet ./...`.
- Деплой на `https://max.iqj.app` и проверка с реальной геопозицией в MAX.

## 3. Критерии готовности (DoD)
1. Житель в любой точке Москвы отправляет геопозицию боту -> бот находит точный дом жителя.
2. При отправке точки из-за МКАД/области бот вежливо предупреждает, что сервис запущен по Москве, и предлагает тестовые московские адреса.
3. Поиск по адресу в мини-приложении находит любой дом в Москве.
4. Созданные дома автоматически привязаны к соответствующему районному отделению ГБУ «Жилищник» с телефоном ЕДЦ +7 (495) 539-53-53.
5. Тесты и линтеры зелёные.
