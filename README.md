# Заявки по дому в MAX

Чат-бот и мини-приложение в мессенджере MAX для коллективных заявок по общему имуществу многоквартирного дома. Трек «Умный город».

- Бот: https://max.ru/t105_hakaton_max_bot
- Демо-стенд: `https://max.iqj.app/` (демо-вход по ролям: `?demo=resident`, `?demo=resident_2`, `?demo=chairman`, `?demo=uk`, `?demo=district`)
- API: `https://max.iqj.app/api/v1`, контракт [`api/openapi.yaml`](api/openapi.yaml), обязательные проверки [`DATA-API.yaml`](DATA-API.yaml)

## Назначение

Когда в доме ломается лифт или гаснет свет в подъезде, десятки соседей пишут в домовой чат, а в управляющую компанию не обращается никто или приходит десять разрозненных звонков. Сервис превращает этот поток в одну доказательную заявку с ответственным, нормативным сроком и живым статусом.

## Возможности

Крупные возможности продукта; список пополняется вместе с кодом.

**Житель**
- **Коллективная заявка без дублей.** Соседи присоединяются кнопкой «Это и у меня», и УК видит, сколько человек ждёт ремонта.
- **Ответственный и срок сразу.** Они определяются по справочнику категорий, рабочие дни считаются по производственному календарю РФ.
- **Три способа сообщить:**
  - одна фраза боту;
  - QR-наклейка в лифте (открывает форму с уже выбранным объектом);
  - форма мини-приложения с фото, черновик которой сохраняется.
- **Бот как полноценный канал.** В нём:
  - одно окно: меню, списки и карточка заявки меняются на месте, как экраны приложения, с кнопками «Назад» и «Меню»;
  - заявка кнопками (категория, подъезд, описание) или одной фразой, текстом или голосовым сообщением (по расшифровке MAX);
  - «Сейчас в доме»;
  - уведомления о каждом шаге УК, живая карточка, которой можно поделиться в чате дома без персональных данных.
- **Проверка ремонта жителями.** 7 дней после «выполнено» участники отвечают «Починили» или «Не починили» с комментарием и фото. Возврат в работу не снимает просрочку.
- **Телефон для мастера.** Подписанный номер из аккаунта MAX оставляют в мини-приложении или кнопкой в боте, видит его только ответственная УК.
- **Обращение в Мосжилинспекцию.** По просроченной заявке готовится PDF с хронологией, числом сообщивших и основанием срока.

**Совет дома**
- Предложения председателю: он видит текст без имени автора и отвечает.
- Опросы жителей без юридической силы: в приложении и прямо в чате с ботом.
- Сводный PDF-реестр проблем дома.

**Управляющая компания**
- **Очередь по срочности** с фильтрами по домам и категориям.
- **Смена статуса** с комментарием и фото выполненной работы; очередь, смена статуса и метрики есть и прямо в чате с ботом.
- **Метрики:**
  - первый ответ;
  - закрыто в срок;
  - подтверждено и возвращено жителями.
- **QR-наклейки A6** для печати и в PDF.
- **Карта нагрузки:** дома УК на карте, размер точки по числу открытых заявок, красный цвет у просроченных; нажатие открывает заявки дома.

**Район и город**
- **Кабинет управы района:** сравнение УК района и все просроченные заявки района; сводка и просрочки доступны и в чате с ботом.
- **Карта района:** все дома района с нагрузкой и просрочками, по ней видно, где жители ждут дольше всего.
- **Вся Москва и Московская область.** Дом по адресу, геопозиции или нажатием на карте создаётся автоматически по данным OpenStreetMap, с подъездами, объектами для QR и районным отделением «Жилищника». Выбор на карте работает и там, где нет геолокации.
- **Импорт реестра домов** из CSV для подключения УК.

## Основной пользовательский сценарий

1. **Житель сообщает о проблеме.** Он пишет боту одной фразой («не горит свет на 5 этаже») или сканирует QR-наклейку в лифте. QR открывает мини-приложение с уже выбранными домом, подъездом и объектом.
2. **Сервис определяет категорию, ответственного и срок.** Он проверяет, нет ли уже открытой заявки. Если есть, житель нажимает «Это и у меня».
3. **Участники получают живую карточку.** Она приходит в чат с ботом, и ей можно поделиться в чате дома.
4. **Сотрудник УК принимает заявку.** Он берёт её в работу и закрывает, указывая комментарий. Карточка у всех участников обновляется на месте, при закрытии приходит итоговое сообщение.
5. **Жители проверяют ремонт.** В итоговом сообщении и в карточке есть «Починили» и «Не починили». «Не починили» с комментарием возвращает заявку в работу, у УК она попадает в группу «Вернули жители».
6. **Если срок прошёл**, участники получают сообщение о просрочке, а в хронологии заявки появляется отметка.

Подробный сценарий проверки: [docs/testing.md](docs/testing.md).

## Состав и архитектура

| Компонент | Технологии | Назначение |
|---|---|---|
| [`backend/`](backend) | Go 1.27, Fiber v3, pgx, sqlc, goose | HTTP API, приём событий бота, бизнес-правила, фоновые задачи |
| [`miniapp/`](miniapp) | Vite, React 19, TypeScript, MAX UI, MAX Bridge | интерфейс жителя и кабинет УК |
| PostgreSQL 18.6 | | дома, заявки, участники, журнал событий, очередь уведомлений |
| Caddy 2.10 | | HTTPS, раздача мини-приложения, прокси `/api` и `/webhook` |

Бэкенд устроен слоями: `domain` → `app` → `transport` и `storage`, зависимости собираются в `cmd/api`. Уведомления бота идут через очередь `outbox` с лимитами Bot API. Подробнее: [docs/architecture.md](docs/architecture.md).

```
MAX (бот, мини-приложение) ──HTTPS──> Caddy ──> api ──> PostgreSQL
                                             └──> Bot API MAX (карточки, уведомления)
```

## Запуск одной командой

Нужен только Docker. Из корня репозитория:

```bash
docker compose -f deploy/compose.yaml --env-file deploy/.env.example up -d --build
```

После запуска откройте `http://localhost/?demo=resident`. Сборка с нуля занимает около двух минут. Бот локально выключен (`BOT_MODE=off`): API и мини-приложение работают без него. Развёртывание на сервере описано в [docs/deployment.md](docs/deployment.md).

## Параметры окружения

- Docker 24+ с плагином compose v2.
- Свободные порты 80 и 15432 на машине. Если порт занят, его можно сменить переменными `HTTP_PORT` и `DB_PORT`.
- Для разработки без Docker: Go 1.27.1, Node 24, [Task](https://taskfile.dev) v3. Команды перечислены в `Taskfile.yml` (`task` выводит список).

## Переменные окружения

Все переменные читает compose из [`deploy/.env.example`](deploy/.env.example). В нём локальные значения без рабочих токенов.

| Переменная | Назначение | Локально |
|---|---|---|
| `DOMAIN` | адрес сайта для Caddy; на сервере домен, для него выпускается сертификат | `:80` |
| `HTTP_PORT`, `HTTPS_PORT`, `DB_PORT`, `S3_PORT`, `S3_CONSOLE_PORT` | порты на машине | `80`, `443`, `15432`, `19000`, `19001` |
| `MINIO_ROOT_USER`, `MINIO_ROOT_PASSWORD` | логин и пароль MinIO, ими же api входит в хранилище фото | `dommax`, `dommax-local-only` |
| `POSTGRES_PASSWORD` | пароль базы | локальный |
| `SESSION_SECRET` | подпись сессий мини-приложения, не короче 16 символов | локальный |
| `DEMO_AUTH_ENABLED` | демо-вход по ролям для проверки | `true` |
| `ROLE_SWITCH_ENABLED` | роль для проверки из MAX: `/role` в боте и переключатель в приложении | `true` |
| `BOT_MODE` | `off`, `polling` или `webhook` | `off` |
| `MAX_BOT_TOKEN` | токен бота MAX | пусто |
| `MAX_WEBHOOK_SECRET` | секрет webhook, 5–256 символов `A-Z a-z 0-9 _ -` | пусто |

Дополнительно api понимает:
- `CONSENT_VERSION`: версия согласия на обработку данных, по умолчанию `v1`;
- `MAX_API_URL`: адрес Bot API, по умолчанию `https://platform-api2.max.ru`;
- `MAX_API_CA_FILE`: свой файл корневых сертификатов;
- `S3_ENDPOINT`, `S3_ACCESS_KEY`, `S3_SECRET_KEY`, `S3_BUCKET`, `S3_USE_SSL`: хранилище фото к заявкам по S3 API. В Docker это сервис `minio`, ключи берутся из `MINIO_ROOT_USER` и `MINIO_ROOT_PASSWORD`;
- `PHOTOS_DIR`: каталог фото на диске, если `S3_ENDPOINT` не задан (локальный запуск без Docker);
- `GEOCODER_URL`, `GEOCODER_USER_AGENT`: геокодер на данных OpenStreetMap, совместимый с Nominatim (адрес при «Найти дома рядом», координаты при импорте домов). Пусто — выключен;
- `OLLAMA_URL`, `OLLAMA_MODEL`, `COMPOSE_PROFILES=llm`: подсказка категории через self-hosted модель (необязательно, см. [docs/deployment.md](docs/deployment.md)).

## Внешние сервисы и интеграции

| Сервис | Зачем | Можно ли проверить в Docker |
|---|---|---|
| MAX Bot API (`platform-api2.max.ru`) | сообщения бота, живые карточки, webhook | нет: нужен токен бота и HTTPS-домен; локально бот выключен, всё остальное работает |
| MAX Bridge | вход по `initData`, кнопка «Назад», шеринг, сканер QR, скачивание PDF, телефон для мастера (`requestContact` с проверкой подписи) | нет: работает только внутри клиента MAX; в браузере есть демо-вход и запасные пути |
| Let's Encrypt | сертификат для домена стенда | не нужен локально |

- **Реальных интеграций** с ГИС ЖКХ и системами УК нет. Дома, УК и объекты модельные, это указано в интерфейсе и в [docs/data.md](docs/data.md).
- **LLM (необязательно).** Подсказку категории может давать self-hosted модель в Ollama: профиль compose `llm`, модель `qwen3:4b`.
  - Модель выбирает только из закрытого справочника, ответственного и срок задают правила.
  - Без модели работают ключевые слова.
  - Подробнее: [docs/architecture.md](docs/architecture.md#подсказка-категории).

## Работа с данными

- **Хранение.** Данные лежат в PostgreSQL, схема создаётся миграциями при старте `api`. Фото к заявкам лежат в MinIO (S3 API), том `minio_data`.
- **Журнал событий.** По каждой заявке хранятся создание, присоединения, смена статуса и просрочка.
- **Персональные данные:**
  - соседи видят только число сообщивших;
  - имя жителя видит только УК;
  - телефон житель оставляет сам через MAX, его видит только УК его открытых заявок;
  - при удалении аккаунта имя и согласие стираются, заявки остаются без данных автора;
  - в логах нет персональных данных и текстов обращений.

- **Открытые данные.** Адреса и координаты от геокодера — данные OpenStreetMap, © участники OpenStreetMap, лицензия ODbL. Подпись показывается рядом с найденным адресом.
- **Импорт реестра домов:** `api import-houses <файл.csv>`, формат и команда для Docker в [docs/deployment.md](docs/deployment.md#импорт-домов-из-csv).

Таблицы и правила: [docs/data.md](docs/data.md).

## Тестовые данные

- **Демо-данные** создают миграции при первом запуске:
  - модельная УК «Ореховый квартал»;
  - шесть домов на Ореховом бульваре с подъездами и объектами с QR-кодами;
  - четыре демо-пользователя и три демо-заявки;
  - 22 синтетические заявки для метрик, они подписаны «Пример данных»;
  - ещё две модельные УК района Зябликово с четырьмя домами и 14 синтетическими заявками для кабинета района.
- **Демо-вход без пароля:** `POST /api/v1/auth/demo` с телом `{"role":"resident"}`. Роли: `resident`, `resident_2`, `chairman`, `uk_operator`, `district`. В браузере работают ссылки `?demo=resident`, `?demo=resident_2`, `?demo=chairman`, `?demo=uk`, `?demo=district`.
- **Идентификаторы, коды QR и примеры запросов:** [`deploy/seed/test-data.json`](deploy/seed/test-data.json).
- **Сброс к исходным данным:** `docker compose -f deploy/compose.yaml --env-file deploy/.env.example down -v`, затем снова `up`.

## Пошаговый сценарий проверки

1. Запустите решение командой выше или откройте демо-стенд.
2. Откройте `/?demo=resident`, нажмите «Сообщить о проблеме», выберите «Лифт», подъезд, текст и отправьте.
3. Откройте `/?demo=resident_2`, найдите заявку в «Сейчас в доме» и нажмите «Это и у меня».
4. Откройте `/?demo=uk`, в «Заявках» откройте заявку, смените статус на «Принята» с комментарием.
5. Посмотрите «Метрики» и «Наклейки» в кабинете УК.
6. В MAX напишите боту https://max.ru/t105_hakaton_max_bot, что сломалось. Бот определит категорию, проверит дубль и пришлёт живую карточку.

Полная версия с API-запросами и автотестами: [docs/testing.md](docs/testing.md).

## Примеры ожидаемого поведения

| Действие | Результат |
|---|---|
| Житель сообщает о лифте по QR `h-17k2-e3-lift` | заявка создана: категория «Лифт», ответственный УК «Ореховый квартал», срок 1 рабочий день, сообщивших: 1 |
| Сосед сообщает о том же | форма и бот показывают существующую заявку и предлагают «Это и у меня» |
| Сосед уже присоединился | в карточке вместо кнопки «Вы среди сообщивших»; повторный `POST /issues/{id}/join` даёт `409 already_joined` |
| Житель пробует сменить статус | `403 forbidden` |
| УК отклоняет заявку без причины | `422 reason_required`, кнопка сохранения неактивна |
| УК меняет статус | карточка у участников в чате с ботом обновляется на месте |
| Истёк срок ответа | отметка «Срок ответа истёк» в хронологии, сообщение участникам, заявка в группе «Просрочено» у УК |
| Участник нажимает «Подготовить обращение» у просроченной заявки | скачивается PDF-черновик обращения в Мосжилинспекцию: адрес, УК, даты, основание срока, число сообщивших, хронология без имён |
| Житель прикладывает фото к заявке | снимок уменьшается и сохраняется без EXIF и геометки; его видят участники заявки и УК, остальным соседям `403` |
| Участник выполненной заявки нажимает «Починили» | в карточке «Вы подтвердили, что починили», у УК растёт число в блоке «Проверка жителями»; повторный ответ даёт `409 already_answered` |
| Участник нажимает «Не починили» без комментария | поле подсвечивается, заявка не меняется; через API `422 comment_required` |
| Участник нажимает «Не починили» с комментарием | заявка снова «В работе» с новым сроком, соседям приходит сообщение, у УК группа «Вернули жители» |
| `GET /api/v1/health` | `{"status":"ok","db":"ok"}` |

## Известные ограничения

Коротко: данные домов и УК модельные, ответственный всегда УК, праздники в сроках не учитываются, бот локально не запускается без токена и HTTPS-домена. Полный список: [docs/limitations.md](docs/limitations.md).

## Остановка и повторный запуск

```bash
# остановить, данные базы сохранятся
docker compose -f deploy/compose.yaml --env-file deploy/.env.example down

# запустить снова
docker compose -f deploy/compose.yaml --env-file deploy/.env.example up -d --build

# начать с чистой базы и исходных демо-данных
docker compose -f deploy/compose.yaml --env-file deploy/.env.example down -v
```

Логи: `docker compose -f deploy/compose.yaml --env-file deploy/.env.example logs -f api`.
