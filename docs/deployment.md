# Развёртывание

## Локально одной командой

Нужен только Docker (Docker Desktop или Docker Engine с плагином compose). Команда выполняется из корня репозитория:

```bash
docker compose -f deploy/compose.yaml --env-file deploy/.env.example up -d --build
```

- **Сборка.** С нуля занимает около двух минут; время первой загрузки базовых образов сюда не входит.
- **Что поднимется:**
  - `web` — Caddy с собранным мини-приложением;
  - `api` — Go-сервис, миграции базы накатываются при старте;
  - `db` — PostgreSQL 18.6.
- **Проверка.** Откройте `http://localhost/?demo=resident`. Состояние сервиса: `http://localhost/api/v1/health`.

| Порт на машине | Сервис | Переменная, если порт занят |
|---|---|---|
| 80 | `web`: мини-приложение и `/api/*` через Caddy | `HTTP_PORT` |
| 443 | `web`: HTTPS, нужен только на сервере с доменом | `HTTPS_PORT` |
| 127.0.0.1:15432 | `db`: Postgres для отладки | `DB_PORT` |

`api` слушает `:8080` внутри сети compose. Наружу он не публикуется: запросы приходят через Caddy.

### Остановка и повторный запуск

```bash
docker compose -f deploy/compose.yaml --env-file deploy/.env.example down
```

Эта команда останавливает сервисы, а данные базы остаются в томе `pg_data`. Повторный запуск — той же командой `up -d --build`: заявки и сессии сохраняются.

Чтобы начать с чистой базы и заново засеять демо-данные, добавьте к `down` флаг `-v` (он удаляет тома).

Логи сервиса: `docker compose -f deploy/compose.yaml --env-file deploy/.env.example logs -f api`.

### Импорт домов из CSV

Реестр домов загружается командой внутри контейнера `api`, файл передаётся через stdin:

```bash
docker compose -f deploy/compose.yaml --env-file deploy/.env.example exec -T api api import-houses - < deploy/seed/houses-sample.csv
```

- В ответ печатается отчёт: сколько домов создано и обновлено, у скольких координаты найдены геокодером, ошибки с номерами строк.
- Пример `deploy/seed/houses-sample.csv`: девять модельных домов района Зябликово и одна строка с несуществующей УК, чтобы было видно отчёт об ошибке.
- Формат колонок описан в [architecture.md](architecture.md#реестр-домов-и-геокодер). Локально без Docker: `task import:houses -- deploy/seed/houses-sample.csv`.
- Геокодер задаётся `GEOCODER_URL` и `GEOCODER_USER_AGENT`. По умолчанию это публичный Nominatim: для сотен домов подходит, для реестра города нужен свой сервер.

### Подсказка категории через модель (необязательно)

Без модели подсказка работает на ключевых словах. Чтобы включить self-hosted модель, раскомментируйте в env-файле две строки и запустите ту же команду `up -d --build`:

```
COMPOSE_PROFILES=llm
OLLAMA_URL=http://ollama:11434
```

- **Первый запуск.** Сервис `ollama-pull` один раз скачивает модель `OLLAMA_MODEL`: по умолчанию `qwen3:4b`, около 2,5 ГБ. Модель хранится в томе `ollama_models`, в образ она не входит, поэтому время сборки не меняется.
- **Ресурсы.** Модели нужно около 4 ГБ оперативной памяти, GPU не требуется.
- **Прогрев.** После старта `api` загружает модель в память. В логе появится `llm warmed up`, до этого работают ключевые слова.

## Сервер (демо-стенд)

**Требования:**
- VPS в России с Docker;
- домен с A-записью на VPS;
- открытые порты 80 и 443.

**Шаги:**

1. Скопируйте `deploy/.env.example` в `deploy/.env` и заполните значения для сервера:

   | Переменная | Значение на сервере |
   |---|---|
   | `DOMAIN` | домен стенда, например `dom.example.ru`; Caddy сам получит сертификат Let's Encrypt |
   | `POSTGRES_PASSWORD` | свой пароль |
   | `SESSION_SECRET` | случайная строка: `openssl rand -hex 32` |
   | `MINIO_ROOT_USER`, `MINIO_ROOT_PASSWORD` | свой логин и пароль MinIO (пароль не короче 8 символов). Порты MinIO открыты только на `127.0.0.1`, наружу их не пробрасывать |
   | `DEMO_AUTH_ENABLED` | `true` на стенде для жюри |
   | `ROLE_SWITCH_ENABLED` | по умолчанию `true`: комиссия переключает роль из MAX; `false` на рабочей установке для УК |
   | `BOT_MODE` | `webhook` |
   | `MAX_BOT_TOKEN` | токен бота из кабинета MAX |
   | `MAX_WEBHOOK_SECRET` | 5–256 символов из `A-Z a-z 0-9 _ -` |

2. Запустите стек: `docker compose -f deploy/compose.yaml up -d --build`. Файл `deploy/.env` compose читает сам.
3. Проверьте `https://<домен>/api/v1/health`. В логах `api` должны быть строки `webhook subscribed` и `api started`.
4. В настройках бота в MAX укажите адрес мини-приложения `https://<домен>/`. Изменение проходит модерацию до 48 рабочих часов, поэтому адрес стенда после этого не меняется.

**Обновление:** `git pull`, затем та же команда `up -d --build`. Миграции накатываются при старте.

**Бэкап:**
- база: `docker compose -f deploy/compose.yaml exec db pg_dump -U dommax dommax > backup.sql`;
- фото к заявкам лежат в MinIO, том `minio_data`: `docker run --rm -v dom-max_minio_data:/data -v "$PWD":/out alpine tar czf /out/minio.tgz -C /data .`.

## Особенности MAX

- **Сертификат Минцифры.** Bot API (`platform-api2.max.ru`) подписан сертификатом Минцифры. Образ `api` при сборке скачивает корневой и промежуточный сертификаты с сайта Госуслуг и добавляет их в системное хранилище.
- **Webhook и polling.** Пока на сервере активна подписка webhook, long polling у разработчиков не работает. Локально бот запускают только с `BOT_MODE=off`.
- **Требования к webhook:**
  - только HTTPS на 443 с доверенным сертификатом;
  - ответ MAX приходит сразу, обработка идёт в фоне;
  - повторно доставленные события отсекаются по таблице `processed_updates`.
- **Отправка сообщений.** Все исходящие сообщения идут через очередь `outbox` с лимитами Bot API: 30 запросов в секунду всего и 2 в секунду на чат.
