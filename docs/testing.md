# Проверка решения

Здесь пошаговые сценарии и ожидаемое поведение. Адрес стенда обозначен как `<домен-стенда>`, при локальном запуске через Docker это `http://localhost`.

## 1. В MAX: бот и мини-приложение

1. Откройте бота: https://max.ru/t105_hakaton_max_bot и нажмите «Начать».
   - **Ожидается:** приветствие и предложение выбрать дом. Кнопка «Отправить геопозицию» покажет ближайшие дома, кнопка «Найти по адресу» откроет мини-приложение.
2. Выберите дом «Ореховый бульвар, 17к2» и напишите одним сообщением: `не горит свет на лестнице в первом подъезде`.
   - **Ожидается:** бот определит категорию «Свет в подъезде» и найдёт уже открытую заявку «Не горит свет на лестнице». Он предложит «Это и у меня» вместо новой заявки.
3. Нажмите «Это и у меня».
   - **Ожидается:**
     - при первом действии бот попросит согласие на обработку данных;
     - после согласия в чат придёт живая карточка заявки: номер, место, статус, ответственный, срок, число сообщивших и кнопки «Открыть заявку» и «Поделиться».
4. Нажмите «Открыть заявку».
   - **Ожидается:** мини-приложение откроет карточку со штампом статуса, шкалой срока, ответственным и основанием срока, хронологией. Кнопка «Поделиться» формирует текст для чата дома без имён.
5. Сотрудник УК (демо-вход в браузере, см. раздел 2) меняет статус этой заявки.
   - **Ожидается:** карточка в чате с ботом обновляется на месте, новое сообщение не приходит. Когда заявку закроют, придёт отдельное итоговое сообщение.

Команды бота: `/new` сообщить о проблеме, `/my` мои заявки, `/house` мой дом и контакты УК, `/help` справка.

## 2. В браузере: демо-вход по ролям

Демо-вход работает при `DEMO_AUTH_ENABLED=true`: на стенде и при локальном запуске.

| Ссылка | Кто |
|---|---|
| `https://<домен-стенда>/?demo=resident` | житель Анна, дом «Ореховый бульвар, 17к2» |
| `https://<домен-стенда>/?demo=resident_2` | сосед Сергей из того же дома |
| `https://<домен-стенда>/?demo=uk` | сотрудник УК «Ореховый квартал» |

### Житель

1. Откройте `?demo=resident`.
   - **Ожидается:** «Мой дом» с табличкой адреса, фактами о доме, УК с кнопкой звонка в диспетчерскую, открытые проблемы дома.
2. Нажмите «Сообщить о проблеме», выберите «Лифт», место «Подъезд 2», напишите текст.
   - **Ожидается:** на втором шаге форма покажет похожую открытую заявку, если она есть, и предложит присоединиться. Иначе на третьем шаге будут ответственный, срок ответа и согласие.
3. Отправьте заявку.
   - **Ожидается:** откроется карточка новой заявки в статусе «Отправлена», сообщивших: 1.
4. В другом окне откройте `?demo=resident_2`, найдите эту заявку в «Сейчас в доме» и нажмите «Это и у меня».
   - **Ожидается:** число сообщивших станет 2. Имена соседей нигде не показываются.
5. Проверьте обращение в жилинспекцию. Откройте просроченную заявку из примера, например «Протечка с кровли»: `?demo=resident_2&startapp=i_0190a000-0000-7000-8000-000000000115`. Нажмите «Это и у меня», затем «Подготовить обращение».
   - **Ожидается:** скачается PDF-черновик в Мосжилинспекцию. В нём адрес, УК, даты подачи и срока, основание срока, число сообщивших, хронология без имён и строки для ФИО и подписи.
   - Если срок ещё не истёк, API ответит `409 not_overdue`, кнопки в карточке не будет.
6. Проверьте удаление аккаунта: внизу «Моего дома» нажмите «Удалить аккаунт» и подтвердите.
   - **Ожидается:** экран «Аккаунт удалён», заявки остаются в доме.
   - Следующий демо-вход вернёт демо-пользователя, согласие нужно будет дать заново.

### Сотрудник УК

1. Откройте `?demo=uk`.
   - **Ожидается:** кабинет УК с вкладками «Заявки», «Метрики», «Наклейки».
   - В «Заявках» сводка «просрочено, срок сегодня, всего открыто» и группы по срочности.
2. Откройте заявку и нажмите «Сменить статус». Выберите «Отклонена» без причины.
   - **Ожидается:** кнопка сохранения неактивна, нужна причина.
   - Выберите «Принята», добавьте комментарий и сохраните. На карточке появится штамп «Принята», комментарий будет в хронологии.
3. Вкладка «Метрики».
   - **Ожидается:**
     - первый ответ жителю: медиана за неделю, столбцы по дням и сравнение с прошлой неделей;
     - сколько сообщений соседей приходится на одну проблему;
     - доля закрытых в срок за 30 дней;
     - подпись «Пример данных».
4. Вкладка «Наклейки»: выберите дом и объект.
   - **Ожидается:** наклейка A6 с QR-кодом. Код ведёт на `https://max.ru/t105_hakaton_max_bot?startapp=o_<код объекта>` и открывает форму с уже выбранным объектом.
   - Кнопка «Распечатать» печатает только наклейку.

## 3. API

Контракт: [`api/openapi.yaml`](../api/openapi.yaml). Обязательные проверки для платформы оценки: [`DATA-API.yaml`](../DATA-API.yaml). Тестовые данные: [`deploy/seed/test-data.json`](../deploy/seed/test-data.json).

```bash
BASE=https://<домен-стенда>/api/v1
TOKEN=$(curl -s -X POST $BASE/auth/demo -H "Content-Type: application/json" -d '{"role":"resident"}' | jq -r .token)
curl -s "$BASE/houses?query=17к2" -H "Authorization: Bearer $TOKEN"
curl -s -X POST $BASE/issues -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d '{"house_id":"h-17k2","object_id":"h-17k2-e3-lift","description":"Кабина не приходит"}'
```

| Запрос | Ожидаемый ответ |
|---|---|
| `GET /health` | `200 {"status":"ok","db":"ok"}` |
| `POST /issues` с объектом `h-17k2-e3-lift` | `201`: категория `lift`, заголовок, статус `sent`, срок по справочнику, `participant_count: 1` |
| `POST /issues/{id}/join` повторно | `409 {"error":{"code":"already_joined",...}}` |
| `POST /issues/{id}/status` жителем | `403 forbidden` |
| `POST /issues/{id}/status` `sent → done` | `409 invalid_transition` |
| `POST /issues/{id}/status` отказ без причины | `422 reason_required` |
| `GET /uk/issues` без токена | `401 unauthorized` |
| `GET /uk/metrics` сотрудником УК | `200`, медианы в минутах, счётчики за 30 дней |

Все ошибки приходят в одном формате: `{"error": {"code": "...", "message": "..."}}` и `Content-Type: application/json`.

В Windows-консоли кириллица в аргументах `curl` может уйти не в UTF-8. Тогда сервер ответит `422`. Передавайте тело из файла в UTF-8 (`--data-binary @body.json`).

## 4. Автотесты

Нужны Go 1.27, Node 24 и Task, для integration-тестов ещё Docker.

| Команда | Что проверяет |
|---|---|
| `task test` | юнит-тесты бэкенда: домен, сценарии, бот, фоновые задачи |
| `task db` и `task test:integration` | тесты на настоящем Postgres: хранилище, весь HTTP API с негативными путями, контейнер зависимостей, проверки из `DATA-API.yaml` |
| `task test:cover` | покрытие бэкенда с порогом: всего не меньше 80%, пакеты домена и сценариев не меньше 80% |
| `task miniapp:test` и `task miniapp:cover` | логика мини-приложения: форматирование, модели экранов, метрики, наклейки |
| `task miniapp:typecheck` | TypeScript в строгом режиме |

Те же проверки запускаются в CI на каждый push.
