# Проверка решения

Здесь пошаговые сценарии и ожидаемое поведение. Демо-стенд: `https://max.iqj.app`. При локальном запуске через Docker вместо него `http://localhost`.

## 1. В MAX: бот и мини-приложение

1. Откройте бота: https://max.ru/t105_hakaton_max_bot и нажмите «Начать».
   - **Ожидается:** приветствие и меню. Если дом ещё не выбран, бот попросит его: «Показать дома рядом» (геопозиция) или «Найти дом по адресу» (мини-приложение).
2. Выберите дом «Ореховый бульвар, 17к2» и напишите одним сообщением: `не горит свет на лестнице в первом подъезде`.
   - **Ожидается:** бот определит категорию «Свет в подъезде» и найдёт уже открытую заявку «Не горит свет на лестнице». Он предложит «Это и у меня» вместо новой заявки.
3. Нажмите «Это и у меня».
   - **Ожидается:**
     - при первом действии бот попросит согласие на обработку данных;
     - после согласия в чат придёт живая карточка заявки: номер, место, статус, ответственный, срок, число сообщивших и кнопки «Открыть заявку», «Поделиться» и «Меню».
4. Нажмите «Открыть заявку».
   - **Ожидается:** мини-приложение откроет карточку со штампом статуса, шкалой срока, ответственным и основанием срока, хронологией. Кнопка «Поделиться» формирует текст для чата дома без имён.
5. Сотрудник УК (демо-вход в браузере, см. раздел 2) меняет статус этой заявки на «Принята», затем «В работе».
   - **Ожидается:** карточка в чате обновляется на месте, и на каждый шаг приходит короткое сообщение «Заявка № N принята» или «в работе» со сроком и комментарием УК. Когда заявку закроют, придёт итоговое сообщение с «Починили» и «Не починили».
6. Нажмите «Не починили» в итоговом сообщении и напишите следующим сообщением, что осталось не так.
   - **Ожидается:** «Заявка снова в работе» с новым сроком. Следующее сообщение снова считается новой проблемой.
7. Отправьте `/menu` и откройте «Мои заявки», затем заявку из списка, затем «Назад».
   - **Ожидается:** одно окно. Нажатия не присылают новых сообщений, а меняют сообщение с меню: список, карточка заявки (статус, срок, ответственный, три последних события, кнопки по состоянию), снова список. На каждом экране есть «Меню». «Сейчас в доме» показывает открытые заявки дома, у чужой заявки есть «Это и у меня».
8. В меню нажмите «Сообщить о проблеме», выберите «Лифт», затем подъезд.
   - **Ожидается:** бот покажет, кто отвечает и до какого срока, и попросит описать проблему. Напишите `кабина стоит на 3 этаже`: придёт «Заявка № N отправлена» и предложение «Оставить телефон для мастера». Эта кнопка присылает номер из аккаунта MAX, бот отвечает «Телефон сохранён». Вместо описания можно нажать «Отправить без описания».
9. Напишите `не работает лифт` и нажмите «Отправить».
   - **Ожидается:** тот же путь текстом. Бот найдёт заявку из шага 8 и предложит «Это и у меня», а при выборе другого подъезда спросит его кнопками.
10. Откройте «Совет дома» (`/polls`).
    - **Ожидается:** открытые опросы дома кнопками, опрос открывается с вариантами, после голоса итоги в процентах. «Предложить совету» ждёт текст следующим сообщением. Председатель (`/role chairman` на демо-стенде) видит «Папку предложений» с кнопками «Взять в работу» и «Отклонить» и может создать опрос: вопрос следующим сообщением, варианты «За», «Против», «Воздержался».
11. На демо-стенде отправьте `/role uk`.
    - **Ожидается:** меню сотрудника УК: «Очередь заявок», «Метрики», «Открыть кабинет УК». В очереди откройте заявку: под карточкой только допустимые статусы. «В работу» меняет статус на месте, «Выполнено» спрашивает комментарий для жителей, «Отклонить» требует причину. Жители заявки получают уведомления. Данные настоящих жителей в этой роли не показываются.
12. Отправьте `/role district`, затем `/role resident`.
    - **Ожидается:** у управы района «Сводка района» с цифрами по УК и «Просрочено в районе». `/role resident` возвращает меню жителя.

Команды бота:
- `/menu` — меню;
- `/new` — сообщить о проблеме;
- `/my` — мои заявки;
- `/house` — мой дом и контакты УК;
- `/polls` — совет дома и опросы;
- `/role` — роль для проверки на демо-стенде: житель, председатель совета дома, сотрудник УК, управа района (`/role uk`, `/role district`, `/role chairman`, `/role resident`);
- `/help` — справка.

## 2. В браузере: демо-вход по ролям

Демо-вход работает при `DEMO_AUTH_ENABLED=true`: на стенде и при локальном запуске.

| Ссылка | Кто |
|---|---|
| `https://max.iqj.app/?demo=resident` | житель Анна, дом «Ореховый бульвар, 17к2» |
| `https://max.iqj.app/?demo=resident_2` | сосед Сергей из того же дома |
| `https://max.iqj.app/?demo=chairman` | Нина, председатель совета того же дома |
| `https://max.iqj.app/?demo=uk` | сотрудник УК «Ореховый квартал» |
| `https://max.iqj.app/?demo=district` | управа района Зябликово, только чтение |

### Житель

1. Откройте `?demo=resident`.
   - **Ожидается:** «Мой дом» с табличкой адреса, фактами о доме, УК с кнопкой звонка в диспетчерскую, открытые проблемы дома.
2. Нажмите «Сообщить о проблеме», выберите «Лифт», место «Подъезд 2», напишите текст.
   - **Ожидается:** на втором шаге форма покажет похожую открытую заявку, если она есть, и предложит присоединиться. Иначе на третьем шаге будут ответственный, срок ответа и согласие.
3. Отправьте заявку.
   - **Ожидается:** откроется карточка новой заявки в статусе «Отправлена», сообщивших: 1.
4. В другом окне откройте `?demo=resident_2`, найдите эту заявку в «Сейчас в доме» и нажмите «Это и у меня».
   - **Ожидается:** число сообщивших станет 2. Имена соседей нигде не показываются.
5. Проверьте обращение в жилинспекцию. Откройте просроченную заявку из примера, например «Протечка с кровли»: `?demo=resident_2&startapp=i_0190a000-0000-7000-8000-000000000115`. Нажмите «Это и у меня», затем «Подготовить обращение».
   - **Ожидается:** скачается PDF-черновик в Мосжилинспекцию. В нём адрес, УК, даты подачи и срока, основание срока, число сообщивших, хронология без имён и строки для ФИО и подписи.
   - Если срок ещё не истёк, API ответит `409 not_overdue`, кнопки в карточке не будет.
6. Проверьте фото. В форме новой заявки под описанием нажмите «Добавить» в блоке «Фото» и выберите снимок JPEG или PNG. Отправьте заявку.
   - **Ожидается:** в карточке заявки появится блок «Фото» с миниатюрой, по нажатию снимок откроется крупно. Под своим фото есть кнопка «Убрать фото».
   - Сосед, который не присоединился к заявке, блока фото не видит.
   - В MAX можно прислать фото боту: оно прикрепится к вашей последней открытой заявке.
7. Проверьте ремонт. В `?demo=uk` отметьте заявку из шага 3 сначала «В работе», затем «Выполнена». Откройте её как `?demo=resident_2`.
   - **Ожидается:** в карточке блок «Проверьте ремонт» с кнопками «Починили» и «Не починили».
   - «Починили»: вместо блока «Вы подтвердили, что починили», в цифрах «1 сосед подтвердил ремонт», в хронологии строка.
   - Откройте ту же заявку как `?demo=resident` и нажмите «Не починили». Пустой комментарий не отправится: поле подсветится. С комментарием заявка вернётся «В работу» с новым сроком, в хронологии будет «Житель вернул заявку в работу: не починили» и комментарий.
8. Проверьте телефон для мастера. Откройте свою открытую заявку.
   - **Ожидается** в браузере: блок «Телефон для мастера» с подсказкой, что номер оставляется в приложении MAX. У `?demo=resident` (Анна) номер уже есть, поэтому вместо подсказки кнопка «Не показывать телефон».
   - В MAX кнопка «Оставить телефон для мастера» открывает окно MAX с запросом номера.
   - Откройте открытую заявку Анны как `?demo=uk`: в карточке блок «Контакты жителей» с номером `+7 999 000-00-01`. Соседи и район этого блока не видят, у закрытых заявок его нет.
   - Если нажать «Не показывать телефон» у Анны, следующий демо-вход вернёт её синтетический номер.
9. Проверьте поиск дома рядом: внизу «Моего дома» нажмите «Другой дом», затем «Найти дома рядом со мной» и разрешите геопозицию.
   - **Ожидается:** список ближайших домов. Если геокодер включён (`GEOCODER_URL`), над списком строка «Вы сейчас здесь: <адрес>» и подпись «© участники OpenStreetMap».
   - Импорт реестра: команда из [deployment.md](deployment.md#импорт-домов-из-csv). Повторный запуск того же файла даёт «создано 0, обновлено 9», строка с неизвестной УК попадает в отчёт.
   - Там же «Выбрать на карте»: карта Москвы. Первое нажатие приближает карту к точке, нажатие на здание ставит отметку. В листе «Какой дом ваш?» ближайшие дома, выбор ведёт на «Мой дом».
10. Проверьте удаление аккаунта: внизу «Моего дома» нажмите «Удалить аккаунт» и подтвердите.
   - **Ожидается:** экран «Аккаунт удалён», заявки остаются в доме, фото этого пользователя из них пропадают.
   - Следующий демо-вход вернёт демо-пользователя в исходное состояние: с домом и согласием.

### Совет дома

1. Откройте `?demo=resident` и прокрутите «Мой дом» до блока «Совет дома».
   - **Ожидается:** опрос «Ставим шлагбаум на въезде во двор?» с вариантами и подписью «Без юридической силы».
   - Выберите вариант и нажмите «Проголосовать»: появятся итоги в процентах (в сумме 100) с отметкой «ваш голос». Второй раз проголосовать нельзя.
2. Нажмите «Предложить совету», напишите предложение и отправьте.
   - **Ожидается:** в «Моих предложениях» оно со статусом «Ждёт ответа председателя». Текст короче 10 символов не отправится.
3. Откройте `?demo=chairman`, в блоке «Совет дома» нажмите «Папка предложений».
   - **Ожидается:** предложения соседей без имён, новые первыми. «Отклонить» без ответа не отправится, поле подсветится.
   - Нажмите «Вынести на опрос» у нового предложения: вопрос и варианты уже заполнены. После «Открыть опрос» он появится у всех жителей дома.
4. Вернитесь в `?demo=resident`: в «Моих предложениях» виден ответ председателя.

### Сотрудник УК

1. Откройте `?demo=uk`.
   - **Ожидается:** кабинет УК с вкладками «Заявки», «Метрики», «Карта», «Наклейки».
   - В «Заявках» сводка «просрочено, срок сегодня, всего открыто» и группы по срочности. Группа «Вернули жители» стоит сразу после просроченных: там заявки, по которым жители сообщили, что не починили.
2. Откройте заявку и нажмите «Сменить статус». Выберите «Отклонена» без причины.
   - **Ожидается:** кнопка сохранения неактивна, нужна причина.
   - Выберите «Принята», добавьте комментарий и сохраните. На карточке появится штамп «Принята», комментарий будет в хронологии.
3. Вкладка «Метрики».
   - **Ожидается:**
     - первый ответ жителю: медиана за неделю, столбцы по дням и сравнение с прошлой неделей;
     - сколько сообщений соседей приходится на одну проблему;
     - доля закрытых в срок за 30 дней;
     - проверка жителями: сколько ремонтов подтвердили и сколько заявок вернули в работу;
     - подпись «Пример данных».
4. Вкладка «Карта».
   - **Ожидается:** сводка «домов с просрочкой, открыто заявок, домов» и карта с домами УК. Дом «Ореховый бульвар, 17к2» — крупная красная точка с числом открытых заявок, дома без заявок — мелкие серые.
   - Нажатие на точку открывает лист дома с его открытыми заявками, из листа открывается карточка.
   - «Списком» показывает те же дома списком, самые проблемные сверху. Внизу карты подпись источников OpenFreeMap, OpenMapTiles и OpenStreetMap.
5. Вкладка «Наклейки»: выберите дом и объект.
   - **Ожидается:** наклейка A6 с QR-кодом. Код ведёт на `https://max.ru/t105_hakaton_max_bot?startapp=o_<код объекта>` и открывает форму с уже выбранным объектом.
   - Кнопка «Распечатать» печатает только наклейку.

### Управа района

1. Откройте `?demo=district`.
   - **Ожидается:** экран «Район Зябликово». Три УК района с цифрами «открыто», «просрочено», «в срок», «первый ответ» и строкой о проверке ремонта жителями. Первой стоит УК с просрочкой («Каширский квартал»), просрочка выделена цветом.
   - Ниже список «Просрочено в районе» с адресами домов разных УК.
2. Откройте просроченную заявку из списка.
   - **Ожидается:** карточка без кнопок «Сменить статус» и «Это и у меня», без фото и контактов жителей: район только смотрит.
3. Нажмите «Карта района» вверху экрана.
   - **Ожидается:** дома всех УК района на карте, дома с просрочкой красные. Житель карту нагрузки не видит: `GET /api/v1/map/houses` с его токеном отвечает 403.

## 3. API

Контракт: [`api/openapi.yaml`](../api/openapi.yaml). Обязательные проверки для платформы оценки: [`DATA-API.yaml`](../DATA-API.yaml). Тестовые данные: [`deploy/seed/test-data.json`](../deploy/seed/test-data.json).

```bash
BASE=https://max.iqj.app/api/v1
TOKEN=$(curl -s -X POST $BASE/auth/demo -H "Content-Type: application/json" -d '{"role":"resident"}' | jq -r .token)
curl -s "$BASE/houses?query=17к2" -H "Authorization: Bearer $TOKEN"
curl -s -X POST $BASE/issues -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d '{"house_id":"h-17k2","object_id":"h-17k2-e3-lift","description":"Кабина не приходит"}'
```

| Запрос | Ожидаемый ответ |
|---|---|
| `GET /health` | `200 {"status":"ok","db":"ok"}` |
| `POST /issues` с объектом `h-17k2-e3-lift` | `201`: категория `lift`, заголовок, статус `sent`, срок по справочнику, `participant_count: 1` |
| `POST /issues/{id}/join` повторно | `409 {"error":{"code":"already_joined",...}}` |
| `POST /issues/{id}/status` жителем | `403 forbidden` |
| `POST /issues/{id}/status` `sent → done` | `409 invalid_transition` |
| `POST /issues/{id}/status` отказ без причины | `422 reason_required` |
| `GET /uk/issues` без токена | `401 unauthorized` |
| `GET /uk/metrics` сотрудником УК | `200`, медианы в минутах, счётчики за 30 дней |

Все ошибки приходят в одном формате: `{"error": {"code": "...", "message": "..."}}` и `Content-Type: application/json`.

В Windows-консоли кириллица в аргументах `curl` может уйти не в UTF-8. Тогда сервер ответит `422`. Передавайте тело из файла в UTF-8 (`--data-binary @body.json`).

## 4. Автотесты

Нужны Go 1.27, Node 24 и Task, для integration-тестов ещё Docker.

| Команда | Что проверяет |
|---|---|
| `task test` | юнит-тесты бэкенда: домен, сценарии, бот, фоновые задачи |
| `task db`, `task s3` и `task test:integration` | тесты на настоящих Postgres и MinIO: хранилище данных и фото, весь HTTP API с негативными путями, контейнер зависимостей, проверки из `DATA-API.yaml` |
| `task test:cover` | покрытие бэкенда с порогом: всего не меньше 80%, пакеты домена и сценариев не меньше 80% |
| `task miniapp:test` и `task miniapp:cover` | логика мини-приложения: форматирование, модели экранов, метрики, наклейки |
| `task miniapp:typecheck` | TypeScript в строгом режиме |

Те же проверки запускаются в CI на каждый push.
