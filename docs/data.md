# Данные

## Что хранится

| Таблица | Содержимое |
|---|---|
| `organizations` | управляющие организации: название, телефоны, график |
| `houses` | дома: адрес, район, год постройки, этажность, подъезды, УК |
| `entrances` | подъезды |
| `asset_objects` | объекты общего имущества с QR-кодами: лифты, освещение, кровля, мусоропровод |
| `users` | пользователи: имя из MAX, роль, дом, район (для управы), телефон для мастера, согласие, отметка об удалении |
| `issues` | заявки: категория, статус, ответственный, срок, последний комментарий УК |
| `issue_participants` | кто присоединился к заявке |
| `issue_events` | журнал событий заявки |
| `issue_photos` | фото к заявке: кто и когда загрузил, размеры; сами файлы лежат в MinIO, бакет `photos` |
| `proposals` | предложения жителей председателю совета: дом, автор (председателю не показывается), текст, статус, ответ |
| `polls` | опросы дома без юридической силы: вопрос, варианты, из какого предложения, до какого времени |
| `poll_votes` | голоса: опрос, житель, вариант; один голос на жителя |
| `issue_confirmations` | ответы участников на «выполнено»: починили или нет, к какой отметке «выполнено» относится ответ, оценка ремонта 1–5 после «Починили» (`stars`) |
| `processed_updates` | ключи обработанных событий бота (защита от повторной доставки) |
| `outbox` | очередь исходящих сообщений бота: адресат, вид, заявка или предложение совету, попытки, время следующей попытки |
| `bot_pending` | что бот ждёт от пользователя следующим сообщением (комментарий «Не починили», предложение совету, ответ председателя, описание до выбора подъезда); запись живёт 10 минут и стирается при использовании |
| `bot_cards` | какое сообщение в чате с ботом — живая карточка заявки у участника |

Схема создаётся миграциями из `backend/internal/storage/postgres/migrations` при старте сервиса.

## Модельные и синтетические данные

Для демонстрации миграции `00002_demo_seed.sql` и `00003_demo_seed_history.sql` создают:

- **УК «Ореховый квартал»:** организация модельная, название и телефоны условные.
- **Шесть домов на Ореховом бульваре (район Зябликово, Москва):** улица реальная, а годы постройки, этажность, число подъездов и координаты условные.
- **Объекты с QR-кодами:** лифт и освещение в каждом подъезде, кровля и мусоропровод каждого дома.
- **Три демо-пользователя:** два жителя и сотрудник УК.
- **Три синтетические заявки** в статусах «в работе», «отправлена» и «выполнена».

Модельные записи домов и организаций помечены полем `source = 'model'`, API отдаёт это поле, чтобы интерфейс показывал пометку.

Миграция `00006_sample_metrics.sql` добавляет пример данных для метрик УК:

- **12 синтетических жителей** без имён, телефонов и аккаунтов MAX. Они нужны только для счётчиков участников.
- **22 синтетические заявки** по шести домам за последние 16 дней. У них есть история статусов, присоединения соседей, закрытия в срок и с опозданием, две открытые просроченные заявки.
- **Пометка.** Синтетические заявки, включая три демо-заявки, помечены полем `issues.sample = true`. Экран метрик в таком случае подписан «Пример данных».
- **Проверка ремонта** (миграция `00009_sample_confirmations.sql`): у 14 из 16 выполненных синтетических заявок автор подтвердил ремонт, одну заявку («Не горит свет на лестнице», Ореховый бульвар, 21к1) житель вернул в работу с комментарием.
- **Оценки ремонта** (миграция `00017_repair_ratings.sql`): у подтверждённых синтетических ремонтов условные оценки. УК «Ясеневый двор» получает 4–5 звёзд, «Ореховый квартал» 3–5, «Каширский квартал» 2–3, чтобы рейтинг района был различимым.
- **Свежесть дат.** При включённом демо-входе (`DEMO_AUTH_ENABLED=true`) сервис раз в 10 минут сдвигает даты синтетических заявок вперёд на целое число дней. Благодаря этому пример не устаревает, а порядок событий и интервалы между ними сохраняются. Заявки настоящих пользователей не затрагиваются.

Миграция `00011_district.sql` добавляет данные для кабинета района:

- **Две УК района Зябликово:** «Ясеневый двор» и «Каширский квартал». Названия вымышленные, телефоны условные.
- **Четыре дома** на реальных улицах района (Ясеневая улица, Воронежская улица, улица Мусы Джалиля). Номера домов, годы постройки, этажность и координаты условные, записи помечены `source = 'model'`.
- **14 синтетических заявок** (`sample = true`). У «Ясеневого двора» быстрые ответы и все ремонты подтверждены жителями, у «Каширского квартала» долгие ответы и три просроченные открытые заявки.
- **Демо-пользователь** «Управа района Зябликово» с ролью `district`.

Миграция `00012_council.sql` добавляет пример совета дома:

- **Демо-председатель** Нина, житель дома «Ореховый бульвар, 17к2».
- **Три синтетических предложения** от демо-жителей: одно ждёт ответа, два председатель взял в работу.
- **Опрос** «Ставим шлагбаум на въезде во двор?» и 7 голосов синтетических жителей.

## Импорт реестра домов

- Команда `api import-houses` загружает дома из CSV (см. [architecture.md](architecture.md#реестр-домов-и-геокодер)). Поле `source` помечает происхождение записи: `import` по умолчанию, `model` для модельных данных.
- Пример `deploy/seed/houses-sample.csv`: улицы района Зябликово реальные, номера домов, годы, этажность и привязка к модельным УК условные, записи помечены `source = model`.
- Координаты домов без координат в файле берутся из OpenStreetMap (© участники OpenStreetMap, лицензия ODbL).

## Дома, найденные по адресу или геопозиции

Если дома нет в базе, сервис находит его в OpenStreetMap по адресу или точке и сохраняет с пометкой `source = 'osm'`.
- **Год постройки и этажность неизвестны** (0), интерфейс их не показывает.
- **Четыре подъезда условны.** Они нужны, чтобы у дома были объекты для заявок и QR-наклеек.
- **Ответственная организация определяется приближённо:** это районное отделение ГБУ «Жилищник» с телефоном Единого диспетчерского центра Москвы. Если район не определился, это сам Единый диспетчерский центр. Реальная УК дома может быть другой, для пилота нужна привязка по реестру (импорт из CSV).

## Подложка карты

Карта домов в кабинетах УК и района и выбор дома на карте используют векторные тайлы OpenFreeMap (`tiles.openfreemap.org`). Сервис бесплатный, без ключей и регистрации, данные карты — OpenMapTiles и OpenStreetMap. Подпись источников показывается в углу карты. В сторону OpenFreeMap уходят только запросы тайлов для видимой части карты, данные сервиса туда не передаются. Дома и числа заявок на карте приходят из API сервиса.

## Сроки ответа

Сроки заданы в справочнике категорий (`backend/internal/domain/rules`) в рабочих днях. Это модельные значения для демонстрации. Перед реальным пилотом их нужно сверить с регламентом управляющей компании и нормативами. Праздничные дни пока не учитываются.

## Персональные данные

- Имя пользователя приходит из MAX при входе.
- Телефон житель оставляет сам, кнопкой «Оставить телефон для мастера» в мини-приложении или в чате с ботом. Номер приходит от MAX с подписью, сервер её проверяет: в мини-приложении подпись `requestContact`, в боте подпись контакта `request_contact`. Номер виден только сотруднику УК, отвечающей за заявки этого жителя, и только пока заявка открыта. Убрать номер можно кнопкой «Не показывать телефон» в карточке любой своей заявки, при удалении аккаунта он стирается.
  - У демо-жительницы Анны синтетический номер `+7 999 000-00-01` (миграция `00010_demo_phone.sql`), чтобы в демо был виден блок «Контакты жителей». Демо-вход возвращает этот номер, даже если проверяющий нажал «Не показывать телефон»: без MAX оставить номер заново нельзя.
- Соседи видят только число участников заявки.
- При удалении аккаунта стираются имя, телефон, согласие, выбранный дом и связь с аккаунтом MAX, а фото пользователя удаляются. Заявки остаются в доме без данных автора, число сообщивших не меняется.
  - Удалить аккаунт можно на экране «Мой дом»: пункт «Удалить аккаунт», затем подтверждение в нижнем листе. В API это `DELETE /me`.
  - Если житель снова откроет приложение в MAX, у него будет новый аккаунт: старые заявки к нему не привязаны, согласие нужно дать заново.
  - Демо-пользователь после удаления при следующем демо-входе возвращается в исходное состояние: имя, дом и согласие. Так проверка удаления не ломает демо и проверки API для других проверяющих.
- Фото к заявке видят только участники заявки и её УК.
  - На телефоне снимок уменьшается до 1600 px и перекодируется ещё до отправки, на сервере это повторяется. Поэтому EXIF с геометкой и данными камеры не сохраняется и даже не уходит с устройства.
  - Житель прикладывает фото только с согласием на обработку данных.
  - Своё фото можно убрать в карточке заявки (`DELETE /photos/{id}`); чужие не может убрать никто, включая УК.
- Логи не содержат персональных данных и текстов обращений.
